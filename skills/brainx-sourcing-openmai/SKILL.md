# 通道 2：外部找人·按职位（OpenMai）

## 通道选择：用户点名优先，未点名才自动选

- **用户明确点名通道**（如「用 OpenMai 找」「按这个职位找人」）→ 直接调用本工具，不得擅自改选其他通道；职位未接单等前置不满足时，如实说明并引导完成前置，而不是悄悄换通道。
- **用户未点名** → 按下面的决策树自动选择（有已接单职位且库内不够时选本通道）。

## 接单流程（用户不碰参数）

1. **定位职位**：用户表达接单意向（职位名、公司名、序号或“这个不错/接了吧”都算）→ 用本轮已展示的推荐列表或简报数据定位唯一职位；本轮没有就调 brainx_daily_brief 拿当日推荐映射；对不上就把候选职位列成简短选项让用户挑。**绝不让用户去找 job_id 或任何参数。**
2. **先给岗位理解再要确认**：定位唯一后，用两三句话说明公司·职位·城市·HC·匹配分·关键风险或缺口（全部来自已取回数据），最后一行固定问“**确认接【公司·职位】这个岗位吗？**”。
3. **确认即接单**：用户回复“确认/接吧/可以/嗯/就是这个”等认可后**立即调用 `brainx_accept_job`，不要再问第二遍**，参数只有 `{ "job_id": "...", "confirm": true }`——目标/首条行动/截止时间由服务端自动生成，不要自己编造；成功后自动启动 OpenMai 找人，按本 skill 的调用契约守候并交付结果。职位无法唯一定位或用户未确认时不得调用；调用失败如实转告，不要静默重试。
## 何时用

- 有**已接单**的具体职位（job_id），库内（brainx-sourcing-reloop）结果不够或为空，需要到猎聘/脉脉/BOSS 外部渠道找人。
- 不适合：还没有职位（转 brainx-sourcing-supermai）；库内已够（先用内部库）。

## 调用契约（触发/读取两段式）

`brainx_openmai_search`，参数 `{ job_id, criteria? }`。职位必须本人 ACCEPTED/COMPLETED，否则返回 JOB_NOT_ACCEPTED（如实告知需先接单）。项目群里顾问可先发送一条以“找人条件：”开头的消息；按钮命令要求使用本群最近一条此类顾问消息正文作为 `criteria`。没有时只传 `job_id`，由职位事实自动找人；不得把机器人消息、历史候选结果或普通闲聊拼进条件。

候选名单后的继续按钮使用 `{ job_id, criteria?, continue_search: true }`。排除名单由 BrainX 从项目历史结构化结果提取并累计，Agent 不得自行传入、手抄或编造 TTC 编号。返回 `cannot_continue` 代表没有可确认的 TTC 编号且未启动新任务。

1. **首次调用 = 触发**：返回 `running` + task_id。真实找人运行通常需要 **数分钟到更久**（窄方向更慢）。
2. **守候纪律（严格遵守，不许提前放弃）**：触发后**至少守候 10 分钟**，每隔 2-3 分钟同参数再调读取状态，**至少轮询 3-4 次**。期间对顾问说「正在搜索中」，不要只等 1-2 分钟就宣布失败；10 分钟后仍 running 就如实说「任务仍在执行中（task_id）」，建议稍后再问——**running ≠ 失败**。系统有 60 分钟兜底自动清理中断任务。
3. **完成后读取**：`status: done` 时 `data.result_text` 是完整候选人清单，**必须完整、结构化地呈现给顾问**，不能只回「已就绪」；`failed` 才是失败，如实转告 error 并建议重试。

## 费用与防重纪律

- done 后同职位复用缓存结果（already_done）；重复找人需顾问明确要求重新搜。
- running 期间不要反复触发；间隔一段时间后再查状态即可。
- 无有效 TTC 凭证会快速失败并提示扫码同步——如实转告，不要臆测结果。

## 结果纪律

结果文本中候选人姓名、公司、匹配理由来自 OpenMai 找人；**没有证据的字段标「待核实」**。筛选条件先用简洁纯文字说明，候选人必须用规整表格完整呈现；每行保留稳定 `candidate_ref` 和对应的 TTC 人才详情页链接，最右侧交由飞书卡片渲染“查看人才”和“保留”操作。保留按钮调用 `brainx_candidate_workflow` 的 `KEEP_FOR_REVIEW`，进入项目共享重点名单。不得输出反斜杠转义、HTML 空格实体、伪造链接或简历附件，也不得引导发送简历。呈现后询问下一步（约面/推荐/加入项目）。
