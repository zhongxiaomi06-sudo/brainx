# 前端真实数据重构施工清单

> 上级入口：[BrainX 文档书](README.md)
> 相关依据：[前端交互架构](frontend-interaction-architecture.md) · [TTC 职位字段库](ttc-field-catalog.md) · [内部 Storybook 组件库](storybook-component-library.md) · [BrainX v2.0 产品需求](prd-2026-08-24-brainx-v2.md)

## 1. 目标与施工边界

本轮重构的目标不是给旧界面换皮，而是让用户看到、筛选和调整的内容都能回到真实数据与真实业务动作。施工遵循以下不可削减规则：

1. TTC 是近期职位数据的主要来源，字段定义以真实 TTC 响应和后端落库结果为准。
2. 数据源没有提供、后端没有推导依据的字段，不得包装成标签、筛选器、分数或状态。
3. 新交互先在 Storybook 使用脱敏的真实字段形状完成审核；用户确认后，才接入正式工作台。
4. 正式页面不得在接口失败、数据为空或字段缺失时静默回退到演示数据。
5. 缺失值统一显示“待确认”或“—”，不得用 `0`、虚构标签或默认分数掩盖。
6. 每一阶段独立提交、独立验证；未通过上一阶段验收，不开始依赖它的正式页面改造。

## 2. 总体状态

| 阶段 | 施工内容 | 当前状态 | 进入下一阶段的条件 |
|---|---|---|---|

| B | Storybook：Excel 式真实职位表 | 已完成，待用户审核 | 用户审核列、密度、筛选方式和缺失状态 |
| C | 正式“全部职位”页面接入 | 待审核 | 阶段 B 获得明确确认 |
| D | Storybook：推荐模式与自定义权重 | 审核稿已完成；dry-run 后端契约待补，待用户审核 | 六维可用性与模式规则固定 |
| E | 正式推荐策略接入 | 待审核 | 阶段 D 获得明确确认 |
| F | 方向画像与职位分类 | 待施工 | 分类依据、证据和置信度可解释 |
| G | 左侧导航与设置中心简化 | 应用外壳暂时保留；设置中心审核稿已完成，待用户审核 | 页面归属、分组和保留范围固定 |
| H | 客户洞察真实性收敛 | 暂时保留 | 用户确认客户洞察的运转逻辑 |

## 3. 分阶段施工清单

### A. TTC 字段与能力底座

- [x] 建立 TTC 职位字段单一权威，记录字段版本、来源、语义和缺失规则。
- [x] 默认主表只允许使用：职位、公司、城市、TTC 状态、HC、Pipeline、主做顾问、最近更新。
- [x] 检查原始职位的必填错误、可选字段缺失和结构异常。
- [x] 用真实覆盖率决定字段能否筛选，避免前端仅凭字段名称开放筛选。
- [x] 标准化 Pipeline 阶段，保留原始摘要以便核对。
- [x] 正式接入前，为前端 API 补齐城市数组、主做顾问、结构化 Pipeline 和字段能力。
- [x] 增加字段覆盖率运行报告，能看见每次同步后哪些筛选可用、哪些应降级。

验收：同一字段不再由各页面自行猜测；职位类型、行业、综合分等无依据字段不能进入默认表格和默认筛选。

### B. Storybook：Excel 式真实职位表

- [x] 新建可复用的 `TtcJobsTable` 生产组件，但暂不接入正式工作台。
- [x] 表格只展示九列：职位、公司、城市、TTC 状态、HC、Pipeline 进展、主做顾问、最近更新、操作。
- [x] 公司、城市、状态、HC、主做顾问采用表头筛选，已应用条件显示为可删除标签。
- [x] 搜索只匹配真实展示字段；多城市职位可被任一单独城市命中。
- [x] HC 和最近更新时间支持排序；空值始终排在有值之后。
- [x] Pipeline 只展示一行阶段摘要，长内容不撑坏表格。
- [x] 字段覆盖率不足时保留已知值，但禁用相应筛选并解释原因。
- [x] 提供默认、缺失字段、能力降级、多城市长内容和无匹配结果等审核场景。
- [x] 用 Storybook 交互测试覆盖筛选、删除条件、搜索、排序、详情回调和缺失值。
- [x] 删除错放在“今日决策”故事中的旧筛选原型及其专用样式。
- [ ] 提交 Storybook 审核地址，等待用户确认；本阶段不修改正式“全部职位”。

验收：页面看起来像一张紧凑、可筛选的职位事实表；不存在职位类型、来源、综合分、招聘意愿、信号轨道等虚假字段。

### C. 正式“全部职位”页面接入

- [ ] 先从接近行数上限的 `workbench.tsx` 中拆出职位页面，禁止继续堆叠。
- [ ] 拆分超限的前端 API 适配文件，再补真实字段映射，避免继续扩大单文件。
- [ ] 用审核通过的 `TtcJobsTable` 替换旧 `JobsView`。
- [ ] 删除前端猜测的商业化、产品、技术等职位类型标签。
- [ ] 删除虚构的来源、综合分、新发布、升温、拥挤、疑似失活等选项。
- [ ] 删除未接通的推荐、面试、Offer 独立列；真实接通后再按业务需要恢复。
- [ ] 删除没有事实依据的信号轨道和职位对比指标。
- [ ] 将“最近反馈”改为真实语义“最近更新”。
- [ ] 接口失败、未登录、无数据和同步中分别展示可解释状态，绝不回退到演示职位。
- [ ] 更新旧的源码断言、适配测试和浏览器链路测试。

验收：正式页面的每一个值、筛选条件和状态都能指出来源；接口异常不会出现看似正常的假数据。

### D. Storybook：推荐模式与六维自定义

- [x] 默认界面用“稳健、均衡、探索”三个模式替代直接暴露六个滑块。
- [x] 下方提供“高级自定义”入口，展开后保留六维滑块。
- [x] 根据当前顾问与快照状态标注每一维：可计算、部分可计算、暂不可用。
- [x] 暂不可用的维度禁用调整并说明缺少什么数据，不伪造效果。
- [x] 方向匹配只引用画像关键词或历史主做项目文本，不使用行业、公司阶段等无依据字段。
- [x] 活跃度、容量、结果和探索维度按现有 scorer 输入如实说明；探索明确为确定性而非随机 AI。
- [ ] 正式接入前新增只读 dry-run 契约，返回同一快照下职位升降及原因；当前审核稿明确阻止无预览保存。
- [x] 明确三个模式的审核权重、探索配额和硬规则边界，其中“均衡”与 baseline-1.1 一致。
- [x] 在 Storybook 完成模式切换、自定义、不可用维度、dry-run 契约示例和窄屏场景，等待用户审核。

验收：用户先选择业务意图，不需要理解算法参数；任何滑块都能说明它使用了哪些真实字段、将产生什么变化。

### E. 正式推荐策略接入

- [ ] 后端保存模式、权重版本和修改人，保留可追溯历史。
- [ ] 推荐结果返回各维贡献、缺失数据和最终原因，不只返回总分。
- [ ] 硬规则（HC、已入职、职位关闭、项目归属、冲突）与可调软权重彻底分离。
- [ ] 缺少关键数据时进入“不可判断”，不得被归一化为低分或零分。
- [ ] 对模式切换、字段缺失、恢复基线和版本回滚增加回归测试。

验收：同一批输入可复现相同结果；用户能解释推荐变化，并可安全恢复基线。

### F. 方向画像与职位分类

- [ ] 以 TTC 职位名称和职位说明建立第一版分类，不直接依赖手工虚构标签。
- [ ] 每个分类保存原始证据、规则或模型版本、置信度和人工修订结果。
- [ ] 先支持真实可得维度：方向、城市、管理属性；行业和公司阶段待数据源证明后再加。
- [ ] 将“画像关键词（顿号分隔）”改为结构化选择和可搜索标签。
- [ ] 区分偏好、排除项和硬约束，避免所有内容混入一个自由文本框。
- [ ] 明确画像备注是否参与推荐；若不参与，界面必须直说“仅供记录”。
- [ ] 分类结果与职位主表联动，但默认只展示最主要的少量分类，详细证据进入详情。

验收：每一个方向标签都能追溯到职位原文或人工确认；用户修订后不会被下一次同步静默覆盖。

### G. 左侧导航与设置中心

- [x] 先在 Storybook 建立独立应用外壳审核稿，不替换正式工作台。
- [x] 审核稿主导航只保留今日决策、全部职位、我的项目、客户洞察。
- [x] 设置中心固定在侧栏底部，并在同一应用外壳内展示四个配置分组。
- [x] 审核稿顶部删除同步状态与提醒，只保留顾问身份和按需 BrainX 助手。
- [x] 增加桌面与窄屏审核场景，图标导航保留可访问名称且无颜色对比违规。
- [x] 在 Storybook 完成设置中心详细审核稿，分为个人资料、数据连接、推荐策略和同步诊断。
- [x] 设置中心只使用已有接口形状：个人画像、飞书授权、TTC 凭证状态、人才库健康、策略版本、同步快照和 TTC 字段报告。
- [x] 增加连接健康、需要处理和窄屏三类场景；没有字段报告时明确显示空状态。
- [x] 团队角色管理没有明确前端契约，本阶段不伪造权限控件；推荐六维调整继续留在阶段 D 审核。
- [ ] 用户确认 Storybook 大板块后，再把外壳结构接入正式工作台。
- [ ] 主导航收敛为：今日决策、全部职位、我的项目、客户洞察（暂时保留）。
- [ ] 数据源和推荐策略移入设置中心，不再占用主业务导航。
- [ ] 设置入口保留在侧栏底部；点击后保持应用外壳，只切换中间内容，不跳出独立网页。
- [ ] 设置中心内部按“个人与团队、数据连接、推荐策略、同步诊断”分组。
- [ ] 接入团队权限前先补齐并验证后端权限契约；不得仅凭姓名在前端写死最高权限。
- [ ] 删除重复设置入口和重复命名，保证同一功能只有一个入口。

验收：左侧导航只表达每天要做的工作；低频配置集中但不脱离当前工作台。

### H. 客户洞察真实性收敛

- [ ] 在运转逻辑确认前保留入口，但不扩建新的预测指标。
- [ ] 当前只展示可核验内容：客户名称、活跃职位数、HC 汇总、最近变化和降温状态。
- [ ] 删除或隐藏没有后端事实的客户热度、合作意愿、转化率和趋势结论。
- [ ] 明确客户、职位和项目三者关系后，再决定客户洞察是列表、详情还是行动队列。

验收：暂时保留不等于继续展示假结论；所有指标都能追溯到职位或项目事实。

### I. 演示回退与全链路质量门禁

- [ ] 演示数据只允许存在于 Storybook、测试夹具或明确的演示模式。
- [ ] 排查正式工作台所有 `真实数据 || 演示数据` 形式的静默回退并移除。
- [ ] 为登录、连接中、同步中、真实空数据、部分字段、接口失败建立独立测试。
- [ ] Storybook 每个新导出组件必须有 story；关键交互必须有 `play` 测试。
- [ ] 检查键盘操作、焦点、表头筛选说明、颜色对比度和移动端横向浏览。
- [ ] 每个原子提交运行快速门禁；用户确认正式接入后运行完整门禁和隔离浏览器链路。
- [ ] 浏览器验证同时检查前端页面、后端响应和真实数据库计数，避免只看页面“像是成功”。

验收：质量门禁能阻止假字段回归、真实接口断链、演示数据泄漏和关键交互失效，而不只是检查代码能否编译。

## 4. 明确暂不施工的内容

- 不删除 TTC 原始字段、历史同步记录或用户数据。
- 不在字段尚不存在时提前增加行业、公司阶段、招聘意愿和转化率筛选。
- 不在 Storybook 审核阶段开发导出、分页、批量操作、完整详情抽屉和列配置。
- 不在客户洞察逻辑未确认前扩展预测模型。
- 不在用户审核 Storybook 前替换正式“全部职位”页面。

## 5. 建议的原子提交顺序

1. `docs(frontend): 建立重构施工清单`
2. `feat(storybook): 增加真实职位表审核预览`
3. 用户审核通过后：`refactor(frontend): 拆分全部职位页面与接口适配`
4. `feat(frontend): 接入真实 TTC 职位表`
5. `feat(storybook): 增加推荐模式审核预览`
6. 用户审核通过后：推荐策略、方向画像、导航设置分别独立提交
7. `test(frontend): 补齐真实数据全链路门禁`

## 6. 每阶段交接格式

每次交接必须说明：

- 本次完成了清单中的哪些条目；
- 哪些页面只是 Storybook 审核稿，哪些已经进入正式应用；
- 使用了哪些真实字段，哪些字段仍不可用；
- 自动测试和浏览器验证结果；
- 下一步是否需要用户审核或授权。
