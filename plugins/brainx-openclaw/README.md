# BrainX OpenClaw Plugin

该原生插件仅向 OpenClaw 暴露受控的 BrainX 猎头决策与业务闭环工具。它从 OpenClaw 运行时读取可信飞书身份，生成 60 秒主体声明，并且只访问本机 `127.0.0.1:3102/internal/v1/agent/tools/<tool>` Agent Gateway。

运行时必须通过服务环境提供 `BRAINX_AGENT_GATEWAY_TOKEN` 和 `BRAINX_AGENT_ASSERTION_SECRET`。不要把密钥写入 `openclaw.json`、插件目录或 Git。

插件不提供 Shell、SQL、文件、浏览器、同步或业务写入能力。顾问使用飞书即可，无需在个人电脑安装本插件。

生产安装器还会同步七个已审核顾问 Skill：今日安排、职位判断、人才事实、人才匹配、沟通草稿、面试准备和个人复盘。Skill 决定 Agent 如何组织工作，原生插件负责受控取数；二者缺一不可。

## 飞书功能首页

已授权顾问在私聊输入 `/brainx` 会直接打开不调用模型的功能卡片。卡片提供今日优先事项、职位推荐、候选人匹配、职位判断、跟进建议和个人复盘六个入口。按钮只发起问答，不直接写业务状态。如果 `BRAINX_BASE_URL` 是 HTTPS，卡片还会显示正式工作台入口。

完整边界和验收流程见 [BrainTex 飞书功能首页](../../docs/2026-09-03-braintex-feishu-home.md)。

## 项目群找人入口

项目群职位卡提供“OpenMai 找人”和“SuperMai 找人”两个显式按钮。顾问可先在群里发送“找人条件：……”再点击；Agent 只读取本群最近一条带该前缀的顾问消息作为本轮补充条件，未提供时由职位事实自动生成。按钮点击就是本次渠道选择；插件会先直接向当前群发送“正在处理找人请求，通常需要 3–5 分钟”，不再只留下平台回执表情。Agent 触发异步任务后结束本轮，结果由 BrainX worker 自动回到项目群。工具仍按项目级运行状态防止多人重复触发和重复费用。

每轮候选名单底部继续提供两个渠道的“继续找人”按钮。继续搜索由 BrainX 自动从历史结构化结果提取、累计并传递 TTC 候选编号排除名单；Agent 不接收也不能编造排除编号。没有可确认编号时失败关闭，不产生新的搜索任务。

候选表格每行提供“查看人才 / 初筛通过 / 收藏”。`KEEP_FOR_REVIEW` 写入项目共享重点名单，并在来源项目群幂等发送一条 TTC 人才链接，由飞书侧已有链接展开规则生成标准人才卡；BrainX 不再拼装第二套候选卡。后续项目群问答从 `brainx_candidate_shortlist.focused_candidates` 读取，不依赖易丢失的模型会话记忆。明确取消时使用 `REMOVE_FROM_REVIEW`；“收藏”仅作演示反馈，不写后端。

候选表格不再显示“为 TA 建决策群”。顾问在项目群自然语言说“为这个人建群”或点名候选人要求建决策群，即构成 `CREATE_DECISION_GROUP` 的本次明确确认；候选人未保留时 BrainX 会先自动加入重点名单。指代不唯一时 Agent 只追问候选人姓名，不猜测。

候选人 Offer 决策群首卡提供“查看 TTC 人才”“生成报告”“更新报告”。首次生成和更新都由 `brainx_candidate_report` 从当前已登记群反查唯一候选人；群内 `/report` 等价于更新报告，会把新记录的文字讨论写入新版本飞书云文档。生产需配置租户 HTTPS 基址并发布飞书文档权限。

## 已有群接管

业务 worker 首次启用时只记录机器人当前所在群作为基线；之后发现的新群会得到一次“绑定现有群”卡。卡片要求输入工作台项目编号，受管飞书表单桥只把 `job_id` 交给 Agent。`brainx_bind_group_project` 不接收 `chat_id`，只能绑定当前消息所在群，并且只接受当前顾问已经承接或共享的职位。绑定前该群只允许这一项工具；成功后才升级为完整项目范围并投放项目职位卡。
