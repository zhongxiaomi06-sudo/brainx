## 1. 问题

`src/server.js` 仍有 625 行，同时负责 HTTP 组装、OAuth/session、人才库 API、业务路由、静态资源
和进程启动。登录与人才路由已有清晰领域依赖，却仍内嵌在总入口，使入口继续占用 500 行存量
例外，也让后续边界收口容易误改鉴权或持久层策略。

## 2. 用户场景与验收

### S1：登录/OAuth 路由独立组装

顾问登录页、OAuth 状态/授权/回调、开发 session 创建和退出由独立 route factory 返回；仍复用
现有 state、session、花名册和飞书令牌能力。回调身份不在花名册时继续失败关闭，开发登录仍只
在 `BRAINX_DEV_AUTH=1` 时开放。

### S2：人才库路由独立组装

人才状态、健康、列表、详情、CSV/简历同步、简历列表和职位人才供给路由由独立 route factory
返回。人才后端继续显式选择并失败关闭，路径必须限制在仓库根目录，人才供给继续按职位可见性
校验；不得新增内存回退或运行期建表。

### S3：总入口只负责组装与传输

`server.js` 通过两个 route factory 合并路由，不再直接导入上述领域实现，物理行数降到 500 以内；
新模块各自低于 500 行，并删除质量门禁中 `src/server.js` 的存量行数例外。

### S4：HTTP 契约完全兼容

路由方法、路径、开放/需登录清单、状态码、错误码、Cookie 属性、重定向、响应字段和依赖注入
入口保持不变。此单元不调整业务规则、数据库 schema、前端、生产配置或启动模式。

## 3. 不做

- 不重写通用 router，不引入框架或依赖。
- 不移动推荐、职位、项目、推送、SSE 或进程启动代码。
- 不连接生产，不迁移、回填、清理或发布。

## 4. 完成条件

- 先增加 route factory 清单、`server.js` 行数和领域字符串归属回归，并确认旧实现下失败。
- OAuth/session 既有 HTTP 回归、人才后端专项及路由健壮性回归通过。
- `server.js` 不超过 500 行且质量门禁基线不再豁免它。
- 快速门禁与最新提交完整门禁通过；不 push。
