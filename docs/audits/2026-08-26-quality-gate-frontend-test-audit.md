# 质量门禁与前端链路测试审计（2026-08-26）

> 上级目录：[BrainX 文档书](../README.md)
>
> 适用场景：维护质量门禁、前端自动化测试和 CI 验收范围

## 结论

原门禁能检查静态质量、生产构建、服务启动和前端资产一致性，但不能证明真实浏览器中的水合、登录、导航、搜索和 API 联动正常。全量测试入口还会递归执行 `_archive/brainx-dev/tests`，造成重复失败和五分钟超时，降低了报告信噪比。

## 日志中确认的问题

| 问题 | 日志或代码证据 | 影响 | 修复 |
|---|---|---|---|
| 归档测试误执行 | `npm test` 使用无路径的 `node --test`，日志同时出现 `tests/*` 与 `_archive/brainx-dev/tests/*` | 重复执行 7 组旧套件，失败重复、耗时失真 | 根测试入口限定为 `tests` |
| 受限环境端口失败 | HTTP、OAuth、SSE 测试统一报 `listen EPERM` | 环境限制被误读为业务回归 | 保留失败关闭；完整门禁必须在允许回环监听的 CI/本机执行 |
| 旧浏览器脚本不可移植 | 写死 `/Applications/Google Chrome...` 和旧端口 `3100` | Linux CI 无法运行，端口口径已漂移 | 改用 Playwright 的系统 Chrome 通道和随机端口 |
| 旧浏览器脚本不会可靠失败 | 多处只打印 `PASS/FAIL`，没有断言汇总 | 页面行为失败仍可能返回退出码 0 | 全部关键行为改为断言，任何失败返回非零 |
| 测试污染共享状态 | 旧脚本依赖正在运行的服务并修改共享开发数据库 | 结果不可重复，也可能影响开发数据 | 每次创建临时 SQLite、独立服务和独立端口，结束后清理 |
| 前端测试偏源码形状 | 现有测试主要匹配源码文本和适配函数 | 无法发现白屏、水合、资源 404、控制台错误或代理断链 | 新增真实浏览器前后端链路检查 |
| 构建重复 | 前端 `npm test` 内先构建，完整门禁随后再次构建 | 浪费时间且阶段职责不清 | 静态测试与生产构建拆开，各执行一次 |

## 新门禁覆盖

快速门禁新增前端静态与适配测试。完整门禁和 CI 按以下顺序执行：

1. 后端与共享逻辑测试，只扫描活动 `tests/`；
2. 前端静态与适配测试；
3. 前端生产构建；
4. 隔离浏览器链路：桌面与移动端渲染、开发登录、工作台 API、搜索、导航、静态资源、页面异常、控制台异常和服务端客户端错误计数；
5. 独立后端烟雾测试。

浏览器检查使用临时数据库、随机回环端口并关闭桥接、定时推送和外部模型，不读取本地 `.env`，不会连接生产数据源或修改开发数据库。

## 边界

本轮不引入截图像素基线。像素级基线容易因字体和渲染环境产生噪声；当前先覆盖会阻断使用的结构、交互与运行时错误。后续若某个稳定页面发生重复视觉回归，应为该页面增加经过审查的小范围截图基线。
