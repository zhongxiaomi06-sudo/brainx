# 通道 3：外部找人·按判据（SuperMai）

## 通道选择：用户点名优先，未点名才自动选

- **用户明确点名通道**（如「用 SuperMai 找」「直接按这个画像搜人」）→ 直接调用本工具，不得擅自改选其他通道；即使没有职位，本通道本就不需要。
- **用户未点名** → 按下面的决策树自动选择（无职位/模糊探索时选本通道）。

## 何时用

- **还没有具体职位**，或用户想自由探索人才市场：「帮我找北京 5 年 React 资深前端」「看看市面上 AI 产品负责人什么样」。
- 有职位但想按更宽的画像补充搜寻（与 brainx-sourcing-openmai 并行不冲突）。
- 不适合：只是想查库内已授权人才（先走 brainx-sourcing-reloop，零成本即时）。

## 调用契约（触发/读取两段式）

`brainx_supermai_scout` 支持两种参数：项目群入口用 `{ job_id, criteria? }`，无职位自由找人用 `{ criteria }`。项目群里顾问可先发送一条以“找人条件：”开头的消息；按钮命令要求使用本群最近一条此类顾问消息正文作为 `criteria`，没有时只传 `job_id`，由后端根据职位事实生成判据。自由找人的 `criteria` 为 5-2000 字，一句话画像（城市+年限+技能+软性要求）。渠道为猎聘、脉脉，人数 6-10 名由系统约定，无需指定。

项目候选名单后的继续按钮使用 `{ job_id, criteria?, continue_search: true }`。BrainX 自动累计历史结果中可确认的 TTC 编号并作为下一轮排除名单；Agent 不得自行拼接编号。自由找人模式不接受 `continue_search`。

1. **首次调用 = 触发**：返回 `running` + task_id（`sm_` 前缀）。
2. **守候纪律（严格遵守，不许提前放弃）**：真实找人通常 **3-10 分钟**完成，窄方向可能更久。触发后**至少守候 10 分钟**：每隔 2-3 分钟以同参数再调一次读取状态，**至少轮询 3-4 次**。期间对顾问说「正在搜索中，一般几分钟内出结果」，不要只等 1-2 分钟就宣布失败。
3. **10 分钟后仍 running**：如实告知「任务仍在执行中（task_id）」，建议稍后再来问，**不得说成「没有结果/搜索失败」**——running 是进行中，不是失败。系统有 60 分钟兜底：万一进程中断，任务会被自动标记失败，届时重试即可。
4. **failed 才是失败**：读到的 status=failed 时如实转告 error 内容，并建议调整判据重试（失败有 60s 冷却）。
5. **done 但 zero 命中**（`empty_reason: NO_MATCHES_FOUND` 或 result_text 为 NO_REPLY）：如实说「本轮没搜到匹配的人」，**建议放宽判据重试**——去掉具体公司名、把窄方向拆成 2-3 个宽方向（如「海外产品 UI 设计」拆成「海外产品经理」+「UI 设计师」分别搜）。不得把空结果说成成功，也不得编造候选人。

## 费用与防重纪律

- 同判据 done 后复用结果（不重复扣费）；想换搜索范围就调整 criteria 措辞再调。
- 失败 60s 冷却内不会重试，force 重试需顾问明确要求。
- 无有效 TTC 凭证快速失败并提示扫码同步——如实转告。

## 结果纪律

每人给出姓名、公司/职位、匹配判断、理由与风险；**无证据写「待核实」**。筛选条件先用简洁纯文字说明，候选人用规整表格呈现；TTC 来源且具备稳定 `candidate_ref` 的候选人应携带对应 TTC 人才详情页链接，并交由飞书卡片在最右侧渲染“查看人才”按钮。不得输出反斜杠转义、HTML 空格实体、伪造链接或简历附件，也不得引导发送简历。外部找人结果与内部库合并时注明来源渠道，库内 candidate_ref 为准。
