# BrainTex 飞书功能首页与新用户指引

> 上级入口：[文档书总目录](README.md) · [OpenClaw 生产运行手册](2026-09-03-openclaw-production-runbook.md) · [飞书卡片审核记录](frontend-reviews/2026-09-03-braintex-feishu-home.md)

## 1. 用户看到什么

顾问在飞书里输入 `/brainx` 后，BrainTex 立即返回一张不经过大模型的功能首页。首页只讲顾问要做的事，不暴露工具名、数据表或系统结构：

1. 今天先做什么；
2. 推荐值得做的职位；
3. 为职位找候选人；
4. 判断一个职位；
5. 看跟进建议；
6. 生成个人复盘；
7. 已配置正式 HTTPS 地址时，打开 BrainX 工作台。

每个业务按钮都会发出一句完整、自然的业务问题，再由 OpenClaw 根据当前飞书身份调用 BrainX 只读工具。用户也可以不点按钮，直接用口语提问。

## 2. 真实能力边界

| 用户入口 | BrainX 主要依据 | 当前边界 |
|---|---|---|
| 今天先做什么 | 本人上下文、今日优先事项 | 只读建议，不代替顾问记录进展 |
| 推荐职位 | 已授权职位事实和冻结推荐 | 不跨项目，不把生成文案冒充数据 |
| 职位判断 | 职位评估、缺口问题 | 事实、推断和建议分开 |
| 候选人匹配 | shortlist、候选人事实、匹配解释 | 人才和职位必须双重授权；不返回联系方式和简历原文 |
| 跟进建议 | 已授权进展和缺口 | 当前不直接发消息或改业务状态 |
| 个人复盘 | 本人指定日期范围的工作数据 | 不默认读取他人数据 |

## 3. 交互实现

- `/brainx` 是 `brainx-openclaw` 插件注册的确定性命令，命令处理器直接返回 OpenClaw `presentation`，不发起模型请求。
- 官方飞书渠道把 `presentation` 渲染为卡片 2.0，把按钮命令包装为回调事件，点击后再按当前用户和对话上下文进入 Agent。
- 命令限定在 Feishu 渠道且要求已授权 sender。按钮值只含业务问题，不含 `open_id`、`chat_id`、tenant、token、联系方式或业务对象 ID。
- `BRAINX_BASE_URL` 只在是 HTTPS 时才显示工作台按钮；本地、非 HTTP 和非法地址不会被放入卡片。
- 按钮不直接写数据。后续若开放发送、记录进展或状态变更，必须单独做确认卡和写权限审核。

## 4. 新用户首次出现时机

当前锁定版官方飞书插件能收到 `im.chat.member.bot.added_v1`，但对该事件只记录日志，没有向外部插件暴露自定义处理口。因此不在仓库里修改安装目录中的第三方代码，也不为同一飞书应用启动第二条事件长连接。

可发布的首批流程是：

1. 管理员将顾问 `open_id` 绑定到 BrainX 授权主体；
2. 在飞书应用说明和发布消息中写明“输入 `/brainx` 打开功能首页”；
3. 顾问首次进入私聊后打开首页，以后可随时重新打开；
4. 待官方插件支持可配置的 bot-added 回复，或我们将飞书通道纳入自有网关后，再将这张同源卡片自动发到新对话。

“输入命令打开”是当前真实可交付能力；“刚添加就无操作自动弹出”仍是渠道插件依赖，不应误标为已完成。

## 5. 验收

- 本地：卡片七个入口、危险 URL 拒绝、未授权拒绝和插件契约自动测试通过。
- 目标环境：重装仓库插件并重启 OpenClaw，在 Mia 私聊输入 `/brainx`，检查卡片样式、六个按钮、HTTPS 工作台和未授权账号的失败关闭。
- 用户审核：实际卡片未在飞书中完成点击审核前，视觉与文案不得记为已通过。
