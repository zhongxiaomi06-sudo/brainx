# 第一批人工打标标准（labeling-standard-v1，2026-08-24）

## 任务

7 位顾问 × 各自最新一轮 Top20 = 140 个（顾问，职位）对，逐条人工标注。
已有真实行为/反馈/结果覆盖的坑（标注表 `existing_label` 列非空）**不用重标**——以真实行为为准。

## 流程

```bash
# 1. 生成标注表（云端恢复后先 npm run data:pull，脚本自动优先读云端副本）
npm run label:export          # → data/labeling/labels-v1.csv
# 2. 按 consultant 列拆分发给各位顾问（飞书表/Excel 均可，别改列名）
# 3. 顾问填写 label + reason 两列后回收
# 4. 幂等导入（先 dry-run 检查再正式导）
node bin/brainx-label-import.mjs --file <回收的csv> --dry-run
node bin/brainx-label-import.mjs --file <回收的csv>
```

## 标注规范

**label（四选一，必填）**

| 值 | 含义 | 训练标签值 |
|---|---|---|
| 会接 | 如果现在有资源，我愿意接这个单 | +2 |
| 会看 | 值得放关注榜继续观察 | +1 |
| 没兴趣 | 这个职位对我没有价值 | -2 |
| 不确定 | 信息不足，无法判断 | 0（训练时剔除） |

**reason（原因码，必填；label=会看/会接时填最贴近的顾虑，没兴趣时填主因）**

`无资源 | 不符合方向 | 客户/职位质量不足 | 当前没精力 | 已有其他顾问推进 | 信息不完整 | 其他`
（与 DISMISS_REASONS 枚举一致，便于和行为事件并集训练）

## 质量规则

1. **独立标注**：不看他人答案、不讨论后再填——我们要的是个人判断分布；
2. **只看卡片信息**：基于导出表里的公司/职位/状态/分数判断，不去额外调研（模拟推送触达时的真实决策场景）；
3. **交叉验证**：导出表会随机混入 10% 重复行（同一职位出现两次），同人两次答案不一致率 >30% → 该顾问整批重标；
4. **时限**：下发后 3 个工作日内回收；
5. **冲突处理**：同一（顾问，职位）重复导入时 label 不同会被记 conflict 并拒绝覆盖（导入脚本非零退出），由 Mia 人工裁决后升 scheme 版本再导。

## 数据落位与隔离

- 写入 `job_outcomes`（stage='人工标注'，value_json={label, reason, scheme:'v1'}），回放（brainx_replay）可见；
- **不影响生产排序**：scorer 只读 `$.rating`，标注行无 rating 字段；
- **禁止**把标注写进 recommendation_feedback（会触发「不感兴趣降权」污染排序）。

## 完成标准（DoD）

- [ ] 140 行中待标行 100% 回收（云端已有打标经 audit 确认后抵扣）
- [ ] 交叉重复题一致率全部 ≥70%
- [ ] 导入结果 conflicts=0、failed=0
- [ ] `npm run data:audit` 显示人工标注总量 ≥140 → 达到网格搜索训练门槛
