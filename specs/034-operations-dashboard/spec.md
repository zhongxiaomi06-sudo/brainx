## 1. 目标与受众

为管理员建立一个来源可追溯、默认只读的运营看板。后台消费者把同步、任务、推荐、真实曝光、业务结果、模型用量、影子评估、职位事实版本、投递和备份证据归一到独立事件流，再生成按租户隔离的读模型；看板 API 和 Web 不扫描在线业务表。

默认租户为当前单租户 `brainx`。管理员沿用显式 allowlist，普通顾问不能探测快照、事件样本或投影操作是否存在。本阶段只在本地代码和测试库增加迁移，不连接生产、不执行生产迁移、备份、发送、发布或 push。

## 2. 数据与投影契约

### S1｜事件入口与幂等

追加迁移为同步批次、异步任务、A 运行/推荐项、模型调用、真实曝光、决策动作、业务结果、影子评估、职位事实版本、投递和备份证据建立窄事件信封。`tenant + source + event_key` 唯一；同一来源重放不得重复。历史数据只在迁移/显式重建时归一一次，日常看板读取不得查询这些原始表。

### S2｜checkpoint、乱序与更正

消费者按租户和流序号保存 checkpoint、更新时间、口径版本、状态、错误与积压。实体当前态按稳定逻辑键投影：迟到的旧状态不能覆盖更新状态；业务更正以 `correction_of` 替换原逻辑结果，不增加一份结果。显式重建删除并重放读模型，不删除或改写事件流和事实账本，产出与增量消费一致。

### S3｜指标口径

读模型至少包含：

- 新鲜度：checkpoint、最大序号、积压、最后事件时间、投影更新时间和失败状态；
- 运营：同步完整/失败、异步任务 pending/running/failed、投递失败；
- 容量与恢复：职位数、事实版本数、按日增长，以及最近备份/恢复验证证据；没有证据时明确 `NOT_REPORTED`；
- 真实漏斗：SERVED、VISIBLE、ACCEPTED、面试、Offer、Onboard，以唯一决策/逻辑结果计数；
- 排序效果：LIVE 发布/失败/弃权、实际推荐项、影子 Top10 overlap/NDCG delta/硬违规和样本量；
- 成本与时延：按 LIVE/SHADOW 分开统计调用、已知用量比例、Token、估算成本、失败数和 P95 延迟；未知用量不按 0 填充；
- 样本成熟度：有归因业务结果的唯一决策数、真实曝光唯一决策数及可解释比例；SHADOW 固定无真实曝光/结果。

### S4｜来源追溯

快照登记每类指标的来源、事件粒度和口径版本。管理员可按受限指标键获取最多 20 条脱敏事件样本，只返回事件 ID、类型、模式和时间，不返回 prompt、密钥、联系方式、原文或完整 payload。

### S5｜Web 看板与权限

设置中心只在管理员接口成功时显示“运营看板”。默认视图先显示新鲜度与阻断项，再显示运营、漏斗、LIVE/SHADOW 成本、排序效果、容量/备份和来源说明；没有数据时显示未知/未上报，不制造趋势、概率或业务结果。普通顾问 GET、投影和重建均返回 `ADMIN_FORBIDDEN`。

## 3. 验收

1. 看板 GET 只读投影表；消费者停用时页面仍可读取最后快照并显示陈旧状态。
2. 同一事件重复、来源乱序、结果更正、增量重跑和完整重建都不多算，重建摘要与增量摘要一致。
3. 每个聚合有来源定义，抽样能从指标回查到归一事件 ID。
4. 真实漏斗、LIVE 成本与 SHADOW 评估/成本严格分开；SHADOW 曝光和业务结果始终为 0/不可用。
5. 同步新鲜度、失败/积压、容量增长、备份、漏斗、排序分歧、成本/Token/延迟和样本成熟度均有明确字段及空状态。
6. 管理员与普通顾问权限有独立 HTTP 回归；Web 有加载、正常、陈旧/积压、空数据、失败和窄屏 Storybook 场景。
7. 专项、快速和完整门禁通过。

## 4. 回滚

关闭投影 worker 后继续保留事件流和最后快照；必要时显式重建读模型。回滚或修复只允许清理派生的 checkpoint、实体态和快照，绝不 UPDATE/DELETE 在线事实账本来“修平”图表。关闭前端入口或移除管理员 allowlist 即可隐藏看板，不影响推荐读写路径。
