# Feature Specification: 顾问个人模型配置

**Feature Branch**: `codex/braintex-deployment-manual`

**Created**: 2026-09-03

**Status**: Approved for planning

**Input**: User description: “不同用户可以配置自己的模型；StepFun 只是某位同事的个人选择，不应成为全员固定模型。”

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置我的飞书 Agent 模型 (Priority: P1)

已获准使用 BrainTex 的顾问从飞书功能首页进入受保护的模型设置页，选择受支持的模型供应商、填写准确的模型名称和自己的凭据，在阅读数据使用提示并明确同意后保存。保存成功后，顾问下一次在 BrainTex 私聊中的普通问题由本人选择的模型处理。

**Why this priority**: 没有个人模型，某位顾问改变服务器默认值会让其他人同时失效；这是多人可用的前置条件。

**Independent Test**: 两名已绑定顾问分别配置不同模型，再各自在私聊中查询模型状态；两人看到并使用各自的配置，互不覆盖，即可独立证明价值。

**Acceptance Scenarios**:

1. **Given** 顾问已登录工作台且已与飞书身份绑定，**When** 顾问提交受支持的供应商、模型、有效凭据并确认数据处理提示，**Then** 系统只为该顾问启用该模型并返回不含凭据的状态。
2. **Given** Mia 已配置 StepFun、Felix 已配置 OpenAI，**When** Mia 再次修改自己的模型，**Then** Felix 的模型、凭据和会话均不改变。
3. **Given** 顾问未勾选数据处理同意，**When** 顾问尝试保存，**Then** 系统拒绝启用模型且不持久化凭据。
4. **Given** 顾问通过飞书消息发送疑似 API Key，**When** BrainTex 收到消息，**Then** 系统不把聊天消息当作模型凭据，且引导顾问使用 HTTPS 设置页。

---

### User Story 2 - 自动获得隔离的个人 Agent (Priority: P1)

获准顾问第一次私聊 BrainTex 时，系统自动为该飞书用户建立独立 Agent、工作空间、会话和认证存储；顾问不需要在个人电脑安装 OpenClaw，也不需要管理员手工复制配置。

**Why this priority**: 个人凭据只有绑定到独立 Agent 才能防止跨顾问复用或会话混淆。

**Independent Test**: 使用两个不同的已授权飞书账号首次私聊，检查它们被路由到不同 Agent，且一个账号的模型状态在另一个账号不可见。

**Acceptance Scenarios**:

1. **Given** 已在飞书白名单但尚无个人 Agent 的顾问，**When** 首次私聊机器人，**Then** 系统创建且绑定唯一的个人 Agent，并保留现有 BrainX 服务端业务鉴权。
2. **Given** 同一顾问重复发消息，**When** 系统已存在个人 Agent，**Then** 系统复用原 Agent，不重复创建、不覆盖其认证存储。
3. **Given** 未在飞书和 BrainX 双重白名单的用户，**When** 私聊机器人，**Then** 系统拒绝访问，不创建可使用业务工具的 Agent。

---

### User Story 3 - 安全更换或停用个人模型 (Priority: P2)

顾问可以随时替换自己的凭据、切换模型或停用个人模型。页面只显示供应商、模型、配置时间和可用状态，不回显完整凭据。

**Why this priority**: 模型密钥会过期、撤销或产生费用，必须能由凭据所有者独立轮换和停用。

**Independent Test**: 顾问替换凭据后，旧凭据不再被该 Agent 选用；停用后，普通模型问答失败关闭，但 `/brainx` 确定性首页仍可打开。

**Acceptance Scenarios**:

1. **Given** 顾问已有个人模型，**When** 提交新凭据，**Then** 系统原子替换本人认证记录，不在响应或日志中出现新旧密钥。
2. **Given** 顾问停用个人模型，**When** 再发送普通问题，**Then** 系统明确提示需要配置模型，不静默借用其他顾问或全局凭据。
3. **Given** 顾问只发送 `/brainx`，**When** 本人没有可用模型，**Then** 功能首页仍然以确定性卡片返回。

---

### User Story 4 - 管理员看见状态但看不见密钥 (Priority: P2)

管理员可以确认哪些顾问已经配置、使用哪个供应商和模型、最近更新时间及失败状态，以便上线验收；管理员和日志均不能读取完整个人密钥。

**Why this priority**: 多人上线需要可运维证据，同时必须保持凭据所有权和最小暴露。

**Independent Test**: 管理状态接口列出六位顾问的非敏感配置状态，任何接口、日志和数据库业务表扫描均找不到完整密钥。

**Acceptance Scenarios**:

1. **Given** 多名顾问已配置模型，**When** 管理员读取上线状态，**Then** 返回顾问、Agent、供应商、模型、状态和时间，不返回密钥、令牌或完整认证对象。
2. **Given** 一名顾问的模型调用失败，**When** 管理员查看状态，**Then** 能看到归一化错误类型，但看不到问题正文、候选人原文或供应商原始响应。

### Edge Cases

- 顾问尚未在飞书中触发个人 Agent 创建时，设置页应给出可操作提示，不能把凭据写入共享 Agent。
- 供应商、模型名称、凭据长度或字符不合法时，保存失败且不运行外部命令。
- OpenClaw 配置正在更新或认证库被占用时，操作应串行、有限重试并明确失败，不留下半配置状态。
- 保存凭据成功但模型选择失败时，系统应回滚新凭据或将配置标为不可用，不能声称启用成功。
- 同一顾问在手机和电脑同时保存时，只允许一个更新成功，较晚请求收到冲突提示后重试。
- 私聊使用个人 Agent；共享群不得使用某一成员的个人密钥。群聊在公司模型未配置时应明确不可用。
- 删除、撤销顾问或移出白名单后，其个人 Agent 不再接收消息，待发任务失效；凭据按管理员批准的保留策略清除。
- 模型供应商不可用、余额不足、模型名被下线时，系统失败关闭，不自动切到其他顾问或未经本人同意的供应商。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每位获准飞书私聊用户建立独立 Agent、会话、工作空间和认证存储。
- **FR-002**: 系统 MUST 以飞书渠道提供的可信用户标识和 BrainX 身份绑定共同确定顾问，不能接受聊天文本或前端提交的 consultant_id 作为身份。
- **FR-003**: 顾问 MUST 能从 `/brainx` 功能首页进入 HTTPS 个人模型设置页。
- **FR-004**: 顾问 MUST 能独立选择已批准的供应商和准确模型名称、录入自己的 API Key，并明确同意该供应商处理经过 BrainX 最小化后的业务数据。
- **FR-005**: 系统 MUST 只把凭据写入该顾问个人 Agent 的认证存储，不得写入 Git、浏览器存储、BrainX 业务数据库、聊天消息、URL、进程参数或应用日志。
- **FR-006**: 系统 MUST 支持至少 OpenAI、Anthropic、Google Gemini 和 StepFun 四类配置；StepFun MUST 是可选个人供应商而非全员默认值。
- **FR-007**: 系统 MUST 对供应商、模型和凭据执行白名单及格式校验，并以无 shell 的固定参数调用受控配置能力。
- **FR-008**: 系统 MUST 将个人模型设置为该顾问 Agent 的显式主模型，且不得修改共享全局模型或其他 Agent 的设置。
- **FR-009**: 顾问 MUST 能查看本人非敏感状态、替换凭据、切换模型和停用个人模型；任何读取接口不得回显完整凭据。
- **FR-010**: `/model` 的无范围操作 MUST 只影响当前会话；非管理员不得修改全局或其他 Agent 的默认模型。
- **FR-011**: 系统 MUST 禁止普通 Agent 之间互读会话或互发消息，并保持 BrainX 工具的服务端身份、对象授权和字段裁剪规则不变。
- **FR-012**: 动态个人 Agent MUST 能使用同一组经过批准的 BrainX Skills 和工具白名单，不获得 Shell、任意网络、文件读写或数据库直连能力。
- **FR-013**: 个人模型配置 MUST 只适用于私聊；共享群只能使用单独批准的公司模型，不得借用群成员个人凭据。
- **FR-014**: 未配置或不可用时，普通问答 MUST 明确失败关闭；不调用模型的 `/brainx` 首页仍 MUST 可用。
- **FR-015**: 系统 MUST 记录不含密钥和业务正文的配置审计事实，包括顾问、Agent、供应商、模型、同意时间、状态、更新时间和归一化错误码。
- **FR-016**: 模型配置更新 MUST 串行并具备超时、冲突和部分失败处理，不得留下跨顾问绑定或共享凭据。
- **FR-017**: 管理员 MUST 能查看所有已授权顾问的非敏感模型就绪状态，但不能获取其完整密钥。
- **FR-018**: 顾问被撤权后，系统 MUST 停止将新消息路由到其个人 Agent，并提供受控的凭据清除流程。
- **FR-019**: 系统 MUST 在生产部署前证明两个顾问配置不同模型时互不影响，并对未知用户、跨人读取、无同意、非法输入和模型不可用路径完成负向验收。

### Key Entities *(include if feature involves data)*

- **顾问模型配置状态**: 顾问与个人 Agent 的一对一关联，保存供应商、模型、配置状态、同意时间、更新时间和非敏感错误；不保存密钥。
- **个人 Agent**: 由可信飞书用户身份唯一确定的 OpenClaw 运行单元，拥有独立会话、工作空间和认证存储。
- **个人模型凭据**: 由顾问提供、仅存于个人 Agent 认证存储的秘密，业务接口只能知道“存在/不可用”，不能读取其值。
- **飞书路由绑定**: 将机器人账号和私聊用户精确映射到个人 Agent 的运行配置；它不替代 BrainX 业务授权。
- **数据处理同意记录**: 顾问对指定供应商和用途的明确同意事实；更换供应商时必须重新确认。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已绑定顾问能在 3 分钟内从 `/brainx` 完成个人模型配置，无需安装 OpenClaw或联系服务器管理员改配置文件。
- **SC-002**: 六名灰度顾问各自的私聊都路由到独立 Agent；任意两人的 Agent、会话和认证状态交叉检查为 0 次混用。
- **SC-003**: 两名顾问分别配置不同供应商后，各完成一轮真实问答且模型归属正确，修改其中一人的配置不会改变另一人的状态。
- **SC-004**: 密钥扫描覆盖 API 响应、应用日志、业务数据库、Git diff 和浏览器持久化，完整凭据泄漏数量为 0。
- **SC-005**: 未授权用户、无同意保存、非法供应商/模型、跨人状态读取和群聊借用个人密钥的负向测试拒绝率为 100%。
- **SC-006**: 模型未配置或供应商故障时，用户在 10 秒内收到可操作的失败说明；系统不借用其他凭据且 `/brainx` 首页仍可用。
- **SC-007**: 生产发布后，六名灰度顾问均能打开个人模型状态页，其中至少两名使用不同配置完成真机私聊验收。

## Assumptions

- 顾问通过现有飞书 OAuth 登录工作台，HTTPS 和无状态会话继续作为设置页身份基础。
- 首版采用管理员批准的供应商目录；任意自定义 Base URL 暂不开放，以避免服务端请求伪造和数据发送到未知目的地。
- 用户提交凭据并勾选提示，视为其授权所选供应商处理后续由 BrainX 最小化、按权限裁剪的模型输入；招聘数据的业务授权仍由 BrainX 独立判断。
- 个人配置服务运行在受控服务器，顾问电脑和手机只需要飞书/浏览器；“自己配置”不等于在本机运行模型。
- 群聊需要独立公司模型策略，首版个人密钥只用于私聊。
- OpenClaw 锁定版本为 2026.7.1-2；升级后必须重新验证动态 Agent、个人认证库和会话模型作用域。
