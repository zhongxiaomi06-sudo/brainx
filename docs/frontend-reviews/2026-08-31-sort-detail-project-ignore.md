## 数据与动作边界

- 排序继续读取同一冻结推荐运行，排序请求可取消旧请求，并在 12 秒超时后恢复交互和显示重试错误。
- “观察”仍保留在精选盘卡片，详情底部不再重复提供“加入关注”；“暂不考虑”和“开始跟进”继续服从服务端合法动作。
- “忽略”只出现在尚未关注或开始跟进的待开始项目。后端关闭当前 `MY_JOB / TEAM_SHARED` membership，保留关系历史，不硬删除职位或事件。
- 已关注或跟进中的项目拒绝直接忽略，用户必须先结束当前动作，防止行动与归属断链。
- 后端依赖：`GET /api/v1/recommendations`、`DELETE /api/v1/opportunities/:id/membership`。

## 状态证据

- 正式入口：`TodayDecisionQueue`、`JobDetailCard` 内的 `CommitmentLoopPanel`、`ProjectsView`。
- 自动验证：推荐与 membership HTTP 专项 15/15、前端静态与适配 35/35、Storybook 组件交互 80/80、前端 ESLint 通过。
- 防卡死证据：切换搜索、排序或刷新时会取消旧请求；最新请求超时后清除加载态，不再永久保留 `is-loading` 的禁用遮罩。
- 删除边界证据：待开始项目删除成功、重复删除幂等、跟进中删除返回 409 均有 HTTP 回归测试。
- 发布环境与版本：当前本地分支，未发布目标环境。
- 本地真实页面：五种视图逐一切换均在约 1.1 秒后恢复，加载状态全部回到 `false`；详情“加入关注”为 0 个，“暂不考虑 / 开始跟进”均为 128×44、12px 圆角；11 个真实项目中 8 个待开始项目显示“忽略”，3 个跟进中项目不显示，浏览器控制台无警告或错误。
- 真实数据验证：本地浏览器没有执行删除写入，删除成功、重复幂等和跟进中拒绝由隔离数据库 HTTP 测试证明；目标环境仍未验证。
