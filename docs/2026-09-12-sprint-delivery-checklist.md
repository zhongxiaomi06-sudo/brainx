## 0. 先决条件：一个必须先拍板的缺口

纪要要求候选人卡片上有 **三个按钮**（查看链接 / 初筛通过 / 一键加入人才库）。代码探测结果：

| 项 | 探测结论 | 位置 |
|-|-|-|
| 候选人卡片现状 | 只有 **1 个**跳转按钮「打开 TTC 人才库」，且为 `multi_url` 纯跳转 | `src/agent-gateway/tools-candidate-actions.js:42-44` |
| 飞书卡片回调通道 | **不存在**。全仓 `src/` 检索 `card.action` / `action.trigger` / `interactive_card` 零匹配 | — |
| 「初筛通过自动推卡」能力 | **已实现**。`brainx_candidate_workflow` 的 `KEEP_FOR_REVIEW` 分支在项目群内会自动推 `candidateShareCard` | 同文件 `:155-163` |

结论：三个按钮里有两个依赖「卡片点击 → 服务端回调」，而服务端目前收不到回调。必须在下列三条路线中选一条，其余任务才能排期：

| 路线 | 做法 | 代价 | 演示效果 |
|-|-|-|-|
| A（推荐） | 卡片按钮全部降级为 `multi_url`，跳回 Web 候选人页并携带 `job_id + candidate_ref`，在 Web 上做「已收藏」变灰 | 需新建 1 个 Web 候选页，零后端改动 | 群里卡 → 点 → 浏览器看到变灰 |
| B | 新增飞书卡片回调 handler | 违反「7 天不动后端」约束 | 群内闭环，效果最好 |
| C | 不新增按钮，沿用群内 @机器人 + 现有 agent 能力 | 零开发 | 与纪要描述不符，评委看不到按钮 |

> 定 A 之前，T10/T11/T12 无法开工。这是全清单唯一的阻塞性决策。
