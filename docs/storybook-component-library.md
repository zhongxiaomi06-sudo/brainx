# BrainX 内部 Storybook 组件库

> 上级目录：[BrainX 文档书](README.md)

本文是 BrainX 可复用前端组件的展示、交互验证和维护入口。组件库直接引用生产组件，不维护第二套演示实现，也不连接生产 API 或真实用户数据。

## 当前收录范围

| 分组 | 生产组件与状态 |
|---|---|
| 基础控件 | 标题、状态标签、抽屉区块、筛选下拉、分段切换 |
| 业务组件 | 今日决策队列、机会列表、精选盘、推荐策略审核稿、方向画像审核稿、客户洞察审核稿、推荐预览、文件夹、事实编辑、判断规则 |
| 承接流程 | 接单、进展、阻塞、终局、释放、已承接行动 |
| 应用外壳 | 完整工作台、主页面大板块重构审核稿、设置中心审核稿、窄屏审核稿、真实数据入口三态、正常错误边界、错误降级界面、Dino 游戏 |

代码清单核对后，所有可渲染生产组件导出均已有 story。除原有基础控件、机会列表、精选盘、事实编辑、规则、承接流程、错误边界与完整工作台外，本轮新增覆盖 `TodayDecisionQueue` 和 `WorkspaceEntry`；后者包含连接中、需要登录和服务不可用三种真实数据入口状态。组件清单测试会以生产导出为准持续检查，不再依赖手工维护数量。

`RootLayout` 与 `Home` 是 Next/Vinext 框架入口，不作为组件重复收录；真实鉴权、SSE、后端联动和路由继续由浏览器前后端链路覆盖。完整工作台 story 通过显式 `demo` 属性使用演示数据，正式应用不会在连接失败时静默切换到模拟职位。

`WorkspaceShell` 是第一阶段主页面结构审核组件：主导航只表达四项日常工作，左下角用户身份菜单承载个人资料和工作台设置入口，顶部不显示同步状态或提醒，BrainX 助手按需展开。该组件当前只进入 Storybook，用户确认前不替换正式工作台外壳。

`SettingsCenterReview` 是独立设置空间审核组件：进入设置后退出日常工作导航，改用“返回应用、搜索、个人与工作台分类”的专用左栏，右侧以简洁行式内容切换个人资料、方向画像、推荐策略、数据连接和同步诊断。`WorkspaceShell` 的独立设置按钮已收进左下角用户身份菜单。页面只使用个人资料、飞书授权、TTC 连接、人才库健康、工作台策略版本和 TTC 字段报告的真实接口形状；没有明确后端契约的团队权限不进入审核稿，Storybook 使用脱敏示例且不请求真实接口。

`RecommendationPolicyReview` 是第三阶段推荐策略审核组件：默认用稳健、均衡、探索三种业务模式组织六维软权重，高级自定义按顾问当前 breakdown 标记可计算、部分可计算和暂不可用。同步完整性、职位状态、项目关系和证据覆盖率等硬规则始终独立展示。当前后端没有不落库的策略 dry-run 接口，因此默认场景明确阻止保存；变化列表只作为脱敏契约示例，不能解释为线上真实排名。

`DirectionProfileReview` 是第四阶段方向画像与职位分类审核组件：当前生效区只把 `profile_keywords` 描述为推荐输入，并明确 `profile_note` 仅供记录；结构化偏好、排除项和硬约束在后端字段及评分语义补齐前禁止保存。职位分类区展示现有 `job_classifications` 的方向、管理属性、置信度、版本、命中与排除词和证据，同时直说 TTC 职位尚未统一进入分类链路、后端也没有人工修订契约。Storybook 的人工修订场景是脱敏契约示例，不代表线上已有能力。

`ClientInsightsReview` 是客户洞察真实性审核组件：严格按 `GET /api/v1/clients` 展示客户名、客户类型、职位总数、活跃职位数、已知 HC、最近职位快照、顾问关系和职位状态。搜索、活跃筛选和排序只使用这些真实字段；客户侧栏不生成反馈速度、转化率、历史入职、招聘意愿、客户评分或经营风险，只提供跳转到该客户职位集合的下钻动作。

## 使用命令

从仓库根目录执行：

    npm run storybook
    npm run storybook:test
    npm run storybook:build

开发服务默认使用 6006 端口。静态构建输出到前端目录下的 `storybook-static/`，该目录是本地产物，不得提交。

## 新增与维护规则

1. story 放在 `frontend/btex-frontend/app/stories/`，命名为 `*.stories.tsx`。
2. 必须导入真实生产组件；仅允许用轻量 harness 管理属性、回调和本地状态。
3. 不请求生产接口，不写入真实数据库，不放入账号、密钥或客户数据。
4. 新的业务组件至少提供默认状态和一个空、异常或边界状态；关键按钮使用 `play` 验证真实交互。
5. Storybook 使用独立 Vite 配置，不加载 Vinext、React Server Components 或 Cloudflare 部署插件。
6. 可访问性面板始终启用。现有浅色视觉体系的对比度问题暂记为警告；新增组件不得通过关闭 a11y 插件隐藏问题。
7. 前端测试会自动扫描生产组件导出；新增组件没有被任何 story 引用时，质量门禁会直接失败。

## 验证与边界

完整质量门禁会执行所有 story 的浏览器交互测试，并生成可部署的静态 Storybook。测试复用系统 Chrome；本地或 CI 缺少 Chrome、无法监听回环端口时应明确失败。

当前已确认的存量风险是浅绿色强调文字、浅灰辅助文字和部分浅色标签未达到自动化对比度阈值。这些结果会保留在 A11y 面板中，后续应以统一调色板迁移修复，不能逐个 story 静默豁免。
