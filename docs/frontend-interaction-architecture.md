# BrainX 前端交互架构

> 上级目录：[BrainX 文档书](README.md)
>
> 适用范围：工作台信息架构、页面流程、交互重构与验收

## 产品界面应解决的唯一首要问题

BrainX 不是另一个 ATS、人才库或管理驾驶舱。顾问打开软件时，首屏必须直接回答：**今天最值得处理哪些职位，以及下一步该做什么。**

数据源、算法参数、客户洞察和 AI 助手都服务于这条决策链，不得与今日待处理队列争夺首屏注意力。管理视角和分析视角使用独立页面，不能混入顾问每日入口。

## 从成熟产品借鉴的交互原则

| 参考产品 | 可借鉴模式 | BrainX 落法 |
|---|---|---|
| [Linear Triage](https://linear.app/docs/triage) | 将新工作放入单一收件箱，先审阅，再接受、拒绝或延后 | 今日决策是待判断队列；用户逐项确认归属、关注、接单或排除 |
| [Salesforce Pipeline Inspection](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/sales_core.pdf) | 汇总指标、机会列表和侧边详情在同一工作面；重点暴露下一步是否过期 | 顶部只保留少量队列指标；列表扫描，右侧详情完成判断和动作 |
| [Greenhouse Current Pipeline](https://support.greenhouse.io/hc/en-us/articles/204636805-Current-pipeline-per-job) | 按职位和阶段查看真实管道，通过筛选定位瓶颈 | 全部职位页负责阶段、来源和状态筛选，不承担今日推荐决策 |
| [Ashby Analytics](https://www.ashbyhq.com/product-analytics) | 支持筛选、细分和下钻，告警用于主动发现问题 | 客户与管理页面提供下钻；异常进入提醒，不在首页堆图表 |
| [Loxo Recruiting CRM](https://hiringmachine.loxo.co/free-ats-crm) | 用统一 pipeline 承载招聘人员日常工作，再按职位、客户和顾问下钻 | 职位状态采用统一动作链，避免多套互相冲突的列表语义 |

参考的是任务结构和信息层级，不复制任何产品的视觉资产、文案或品牌样式。

## 权威信息架构

1. **今日决策**：个人待判断队列。提供最新完整运行的全部冻结推荐，每批20条分页；显示决策层级、推荐理由、关键事实缺口、允许动作和数据新鲜度。完整规则见[推荐队列与职位决策产品架构](recommendation-queue-product-architecture.md)。
2. **全部职位**：顾问可见职位的检索、筛选和批量扫描页。
3. **我的项目**：已关注、已接单、待推进和待记录结果的职位。
4. **客户洞察**：按客户聚合真实职位事实；没有后端事实时不得展示模拟经营指标。
5. **连接与数据**：TTC 职位源、飞书授权、同步快照和 RDS 人才库状态。
6. **策略设置**：顾问画像、推荐权重与系统规则。

AI 助手是按需打开的上下文工具，不是常驻第三栏。它读取当前页面或当前职位，但不能遮挡主列表，也不能替代确定性规则与允许动作。

## 用户进入系统后的状态顺序

### 1. 正在连接

页面显示稳定骨架和“正在确认登录与职位快照”，不得先闪出演示职位。

### 2. 未登录

明确显示登录入口、花名册身份要求和开发环境快捷登录。职位、客户、项目页不得静默回退到模拟数据。

### 3. 已登录但无职位快照

明确说明：TTC 是职位权威源，RDS 是人才库旁路，两者不能相互替代。首要按钮进入“连接与数据”，完成 TTC 连接或检查同步状态。

### 4. 已连接且有完整快照

进入今日决策队列。首屏顺序固定为：数据新鲜度与待办摘要 → 筛选 → 职位列表。精选盘是辅助暂存区，默认折叠，不得压在队列之前占据整屏。

### 5. 同步不完整或服务异常

保留最近完整快照时必须显式标明时间和降级原因；没有可信快照时停止展示新判断。网络故障、未登录和空数据是三种不同状态，文案和恢复动作必须不同。

## 列表与详情规则

- 列表用于快速扫描：职位、客户、阶段、关系、决策层级、主要理由、关键风险、数据可信度和唯一下一步；综合分和抽象覆盖率不得替代这些可解释信息。
- 点击行或“详情”打开不跳页的职位事实层，不丢失筛选上下文；“全部职位”使用居中事实卡，不能通过固定右栏挤压主表。
- 详情按顺序呈现：结论 → 关键事实 → 为什么 → 风险 → 允许动作 → 决策轨迹。
- 未被后端允许的动作不显示；UNKNOWN 必须写成“待确认”，不能写成 0 或伪造值。
- 精选盘只负责暂存和整理职位，不承担批量接单；接单必须在单个职位上完成，并明确目标、首个行动和期限。
- 同一动作只保留一个主入口，避免卡片、精选盘和详情同时出现语义不同的“确定”。

## 首轮重构验收

1. 真实应用不再因 401 或服务异常静默显示演示职位；演示数据只能通过显式 `demo` 属性进入。
2. 未登录、服务不可达、无职位快照、同步不完整和正常就绪均有独立可执行状态。
3. 今日决策在桌面端不默认打开 AI 助手；核心列表获得主要宽度。
4. 精选盘默认折叠，今日队列在首屏可见。
5. 导航名称与后端职责一致，不再把客户洞察称为人才库。
6. 上述状态进入 Storybook，并由浏览器交互测试覆盖真实登录和职位展示链路。
