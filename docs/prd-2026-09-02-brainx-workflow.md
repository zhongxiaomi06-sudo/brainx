>
> 文档身份：**本仓库唯一项目级产品 PRD**。本文以 2026-09-02 用户最新明确需求为裁决依据；
> 8 月职位决策工作台 PRD 降为历史产品基线，9 月群聊工作流技术 PRD负责交互、安全与权限架构。

## 1. 产品目标

BrainX 是以飞书群聊为主要工作入口、以 BrainX / Workflow Hub 为业务真值的猎头业务工作流。
它把分散在职位群、项目群和 Offer 群中的信息，串成“职位录入 → 接单判断 → 找人 → 推荐 →
约面/一面 → 后续面试与 Offer → 入职/关闭”的可追溯闭环。

产品在一面前后采用两种不同工作方式：

| 阶段 | 产品角色 | 目标 |
|---|---|---|
| 一面之前 | **AI Leader** | 主动识别机会、串联任务和后台执行器，把工作推进到一面 |
| 一面之后 | **日历助手** | 告诉顾问哪些工作未完成、下一步是什么、何时到期；只提醒，不替人决定 |

职位决策工作台继续存在，但它是职位事实、推荐、项目和行动的操作界面，不再代表整个产品。

## 2. 用户与核心问题

| 用户 | 当前问题 | BrainX 提供的结果 |
|---|---|---|
| 顾问 | 信息散落在多个群，容易漏接单、漏跟进、漏 Offer 动作 | 当前职位、当前项目、唯一下一步和到期提醒 |
| 团队长 | 看不到跨群真实进度，依赖人工日报和记忆 | 可回放的团队工作事实与异常清单 |
| 合伙人/项目负责人 | 发出职位后不知道是否被识别、承接和推进 | 从群消息到职位事实、承接和交付结果的闭环 |
| 客户/候选人 | 不应看到内部判断、隐私和未经批准的内容 | 仅在授权场景下看到白名单安全视图 |

## 3. 核心业务链路

```text
登记群中的职位/项目消息
  → 提炼为带原文证据的事实草稿
  → 顾问确认后进入职位权威事实
  → 接单判断
  → 后台找人与候选人推荐
  → 顾问接受或回流重筛
  → 约面与一面
  → 后续面试、Offer、入职或关闭
  → 全程事件留痕、待办提醒与回放
```

### 3.1 一面之前：AI Leader

1. 从已登记且允许读取的群接收职位信息；未知群默认拒绝。
2. 把消息提炼为带证据的职位事实草稿，不直接覆盖权威数据。
3. 顾问确认草稿后，职位进入统一职位域与推荐/接单链路。
4. 顾问接单后，系统启动受限的后台找人任务并返回可审查结果。
5. 顾问选择接受候选人或回流重筛；AI 可以建议，不能替顾问决定。
6. 形成约面与一面事实，使一面成为前后两段工作流的明确交接点。

### 3.2 一面之后：日历助手

1. 从真实项目状态、行动和截止时间计算待办，不从聊天文案猜测完成度。
2. 对即将到期、已逾期、缺少下一行动和关键事实陈旧的项目提醒顾问。
3. 顾问记录进展、阻塞、释放、入职或关闭；系统保留历史并更新下一步。
4. Offer 阶段仍由人负责谈判和承诺，AI 只负责提醒与材料草稿。

## 4. 产品边界

### 4.1 必须遵守

- **AI 只提议，人做决定**：接单、对外发送、阶段推进、Offer、关闭等写动作必须由有权的人明确确认。
- **群是入口，不是真值库**：权威业务状态只在 BrainX / Workflow Hub；群中内容是输入或投影。
- **默认拒绝**：未登记群、身份不明、资源关系不成立或状态不合法时不得读取或写入业务事实。
- **证据先行**：从群消息提炼的字段必须能指回原始消息证据；无证据不得升级为权威事实。
- **内外隔离**：候选人隐私、薪资底线、内部评价和其他机会不得进入外部群视图。
- **幂等可回放**：重复消息、重复点击和任务重试不得产生重复事实或重复业务动作。

### 4.2 职责边界

| 组件 | 产品职责 |
|---|---|
| 飞书群聊/机器人 | 消息入口、卡片确认和结果展示 |
| OpenClaw/Agent | 对话理解、上下文编排和草稿，不做权限裁决 |
| BrainX / Workflow Hub | 身份、权限、状态机、业务事实、事件账本、幂等与回放 |
| 工作台 | 查看、核验和操作统一业务事实 |
| OpenMai / reloop | 受限后台找人与候选人域能力 |

## 5. 当前 MVP 范围

### P0：先让主链路真实可运行

1. 登记群消息能够自动进入事件账本并被消费者处理。
2. 职位相关消息生成可见草稿；顾问确认/拒绝后形成可追溯结果。
3. 确认后的职位事实进入现有推荐、接单和项目链路。
4. 失败事件可发现、可安全重试，不形成静默黑洞。
5. MCP 写工具继续执行可见性、身份和状态守门。

### P1：形成可演示业务效果

1. 接单后自动启动找人任务，结果经脱敏后返回顾问。
2. 待办提醒从“推荐新职位”改为“哪些活没干、下一步是什么”。
3. 到期前提醒、逾期加急和缺少下一行动提示能够从真实状态产生。

### P2：补齐完整业务生命周期

1. 建立约面与一面事实及合法状态迁移。
2. 在真实消息 gold set 上引入可关闭的 LLM 提炼，提高规则未覆盖字段的准确率。
3. 在安全门禁完成后试点外部群白名单视图和人工审批链。

## 6. 产品验收标准

1. 一条登记群中的真实职位消息能够自动形成一条带证据草稿；重复投递不重复创建。
2. 顾问能够看到并确认或拒绝草稿；确认后职位事实可被推荐和接单链路读取。
3. 从接单到找人结果、接受/回流至少完成一次真实业务演练，全程能回放操作者与结果。
4. 顾问能够收到基于真实行动与截止时间的待办提醒，而不是固定推荐文案。
5. 未登记群、越权顾问、非法状态和重复操作均被拒绝且有审计证据。
6. 一面前后的产品行为符合“AI Leader 主动串联 / 日历助手只提醒”的分工。
7. 完整质量门禁通过；发布与真实数据验证分别留证，不以本地代码存在代替上线。
