# 2026-08-28 前端状态对齐审计

## 审计目标

首次建立 Storybook、用户审核、正式应用接入、目标环境发布和真实数据验证的共同基线。本文记录本次只读调查的证据和差异；当前状态以[中央台账](README.md#当前中央状态)为准。

## 审计范围

- Storybook 中现有审核组件与场景。
- 正式 `workbench` 的 import、路由和点击详情调用链。
- `GET /api/v1/radar` 到居中职位弹窗的数据映射。
- 2026-08-27 版前端施工清单及用户提供的 2026-08-26 旧版副本。
- 本地 Git 历史、组件测试记录和现有文档；本次没有核验云端部署版本。

## 已接入正式应用代码

以下审核组件能从正式入口追踪到真实 import 和渲染调用：

- `WorkspaceShell`：正式日常工作外壳。
- `SettingsCenterReview`：正式设置中心，由 `WorkbenchSettingsPage` 提供真实连接与诊断数据。
- `TtcJobsTable`：正式“全部职位”表格。
- `ClientInsightsReview`：正式客户事实索引。
- `WorkspaceEntry`：连接中、需要登录和服务不可用入口。
- `JobDetailCard`：仅接入正式“全部职位”页面。

## 已完成但仍是 Storybook-only

- `JobsWorkspaceReview`：最新现代职位工作区整体审核稿，未接入正式路由。
- `RecommendationPolicyReview`：推荐模式和六维自定义审核稿；缺少只读 dry-run 后端契约。
- `DirectionProfileReview`：方向画像和职位分类审核稿；缺少结构化保存、评分语义和人工修订契约。

## 发现的状态冲突

施工清单原先把“今日决策卡与全部职位行复用同一个居中详情组件”标记为完成，但正式代码仍有两条路径：

- 今日决策调用旧 `DecisionDrawer` 右侧抽屉。
- 全部职位调用新 `JobDetailCard` 居中弹窗。

因此统一弹窗只能标记为“部分接入”，不能标记为整体完成。本次同步将对应任务退回未完成。

## 备注缺失的数据链路

`JobDetailCard` 组件已经声明并能够展示 `notes`，数据库职位事实也保存备注；但正式“全部职位”链路存在两个缺口：

1. `radarRows` 没有把 `job_facts.notes` 放入 `GET /api/v1/radar` 的职位行。
2. `toJobDetail` 没有把备注映射到弹窗数据。

同一链路还没有向弹窗映射完整的优先级、推荐理由和最近动态。它们必须分别核对真实来源，不能用 Storybook 示例补齐。

## 清单统计

用户提供的 2026-08-26 旧版清单共有 66 项，其中 15 项已勾选、51 项未完成。仓库调查前的 2026-08-27 版共有 97 项，其中 78 项已勾选、19 项未完成。

本次按代码证据退回一项错误勾选，并新增一项备注数据链路任务。更新后施工清单共有 98 项，其中 77 项已完成、21 项未完成。

## 本轮用户结论

- 已确认：保留居中大弹窗的视觉与交互形式。
- 已确认：今日决策与全部职位打开后应使用完全相同的详情结构。
- 已确认：备注必须保存并展示，允许视觉折叠，但不得因入口不同而省略。
