# 已有群首次接管与职位绑定复核

> 上级入口：[前端审核台账](README.md) · [文档书总目录](../README.md)

## 审核身份

- 审核日期：2026-09-11
- Storybook 场景：不适用；这是飞书原生 Card 2.0
- 对应 commit：本记录所在的“群接管”原子提交
- 审核范围：机器人加入已有群后的首次卡片、职位编号提交、权限升级和项目卡接续

## 用户结论

- 已确认：该能力属于当前 P0；用户要求机器人进入已有群后能够接上接单、建群和找人链路，并授权逐项实现。
- 未确认：绑定卡视觉、10 分钟发现延迟、桌面端/手机端表单回调、外部群可用性和错误提示尚未真机复核。
- 正式接入授权：允许接入正式代码；不等于允许标记已发布或真实验证通过。

## 数据与动作边界

- 真实字段：飞书群 ID、群名、账号/租户身份、顾问已承接或共享的 `project_id`、项目 sender/purpose/scope。
- 缺失字段：机器人无法安全从群名推断职位；因此由已授权顾问提交项目编号。
- 后端依赖：飞书 `im:chat` 权限、唯一账号身份绑定、常驻业务 worker、Agent Gateway 和受管表单兼容桥 V2。
- 允许动作：首次建立群基线；发现新群；发送一次绑定卡；绑定当前群到本人有权职位；成功后发送项目卡。
- 禁止动作：客户端传入 `chat_id`；绑定无权职位；绑定前读取项目/人才数据或启动找人；上线时轰炸历史群。

## 状态证据

- 正式入口：`src/worker.js` 启动群接管 worker；`brainx_bind_group_project` 已加入生产工具目录和插件白名单。
- 发布环境与版本：本机联调版本 `1.3.13`；生产未发布。
- 自动验证：覆盖群列表分页、首轮基线、系统项目群跳过、未知群单卡、待绑定单一能力、无权工具拒绝、绑定后 scope 升级和项目卡投放。
- 真实数据验证：未验证；必须用新建测试群完成一次端到端操作后才能升级状态。

## 验收清单

1. 首次启动 worker 不给当前历史群补发卡片。
2. 将机器人加入一个新测试群，10 分钟内出现一次绑定卡。
3. 提交无权或不存在的项目编号，明确失败且群仍保持最小权限。
4. 提交当前顾问已承接/共享的项目编号，群收到项目卡并可继续选择找人渠道。
5. 重复扫描或重复提交不创建第二个职位群关系，也不重复扩大权限。
6. 桌面端和手机端各验证一次表单与工作台深链。
