# 飞书职位摘要与候选人三动作复核

> 上级入口：[前端审核台账](README.md) · [文档书总目录](../README.md)

## 审核身份

- 审核日期：2026-09-11
- Storybook 场景：不适用；职位推荐与候选人名单均为飞书原生卡片
- 对应 commit：以本次原子提交为准
- 审核范围：对话职位推荐的稳定输出格式，以及候选人行末动作

## 用户结论

- 已确认：职位推荐必须自行总结简单、明了、能加快筛选的信息，不能把 score、QOD 或内部参数当作主要内容。
- 已确认：输出固定为“职位简介 / 适合原因 / 需要确认”三段；旧版“结论 / 关键依据 / 主要风险”只作为输入兼容，不再作为新输出口径。
- 已确认：候选人行保留“查看人才”，并增加“初筛通过”和“收藏”。
- 已确认：“收藏”只做比赛演示反馈，不调用工具、不写后端、不声称已写入人才库。
- 未确认：卡片整体视觉和布局后续单独设计；本轮不把格式修改解释为视觉审核通过。
- 正式接入授权：允许接入飞书正式卡片生成与 OpenClaw 提示词。

## 数据与动作边界

- 真实字段：职位公司、名称、ID、已授权职位事实、顾问方向画像、候选人引用与 TTC 人才链接。
- 缺失字段：没有证据的岗位信息统一写“待进一步核验”或“暂无明确待确认信息”，不得由模型补造。
- 后端依赖：“初筛通过”复用受控 `KEEP_FOR_REVIEW`，由 BrainX 写入项目共享重点名单并在当前项目群投放标准人才卡。
- 无后端动作：“收藏”仅返回“已收藏”的展示反馈，不写数据库，也不改变候选人状态。

## 状态证据

- 正式入口：`plugins/brainx-openclaw/prompt.js`、`response-card.js`、`candidate-table.js` 与 `src/openmai-delivery.js`。
- 发布环境与版本：本机 BrainX 飞书环境已安装 `1.3.17`，未发布目标服务器。
- 自动验证：覆盖新三段格式、旧字段兼容、三按钮顺序、初筛受控参数、收藏零工具契约和无效链接失败关闭。
- 真机验证：1.3.16 首轮实测发现 OpenClaw 锁定版原生卡清洗器会丢弃 `column_set`，且只接受 `ocf1` 回调信封；1.3.17 已改为顶层候选摘要与三个顶层按钮，并使用锁定版协议信封，待同轮复测按钮显示与收藏回调。
- 真实数据验证：真实职位重生成已恢复业务网关配置，但职位源返回 `SOURCE_UNAVAILABLE`，未用旧数据冒充成功结果。
