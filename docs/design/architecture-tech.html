AI Native 猎头工作流 · 技术架构图

2026-09-01 v1.2 · 五层架构 · Workflow Hub 是契约与持久事件层，不是第三套业务产品

① 入口层

页面是工作面，对话是动作入口；所有写动作仍经过领域守卫

B-tex Web 临时载体

  • 职位决策、项目行动、Case 时间线
  • 身份确认/拆分队列、失败重试和 DLQ 入口

飞书机器人 终态

  • 查项目/Case、候选人同意、话术终审、录结果
  • 草稿展示 ≠ 已发送；写动作需要显式确认

reloop Web + TalentLens 人选工作面

  • 人才、简历、Mapping、匹配、触达和阶段
  • 招聘网站撞库只产外部身份与证据引用
▼

② 领域服务层

一个事实一个 owner；两产品各自写自己的领域

BrainX · 职位与行动

  • 冻结推荐、membership、decision_events
  • commitment_actions、job_outcomes、回放与合法动作
  • 现有表经 Contract Adapter 输出标准事件

reloop · 人选与触达

  • FastAPI + RDS：candidate、resume、position、match
  • Mapping、activity、interaction、submission/pipeline
  • 拥有人选 canonical identity 和多简历 provenance
▼

③ Workflow Hub · 身份 / Case / 持久事件

首版复用 BrainX 资产并写 reloop 连接器；不用 Kafka，不另起业务产品
Identity Resolverentity_links：显式 ID 优先；模糊匹配进人工队列；支持 verify、unmerge/split 和多简历归一。
Case State Machine职位×人选 case_id；业务里程碑 + 触达双轴；守卫、乐观锁、乱序和 stage_corrected。
Durable Ledger + Sagaworkflow_event_log、processed_events、outbox/inbox、failed/timeout、补偿、DLQ 与 upcasting。
Projection + Contextworkflow_cases、case_context、当前行动、SLA；记录事件水位、模型、提示词和知识版本。
▼

④ AI、知识与证据层

AI 读投影和证据引用；建议本身也可回放

OpenMai / LLM

  • sourcing run、简历结构化、匹配解释、话术与下一行动草稿
  • ai.context_built / shown / accepted / edited / rejected

蒸馏知识库 分级发布

  • Felix v0.5：确认项与待确认项分离
  • Miya v0：仅 DRAFT，不进入自动执行规则
  • DRAFT → CONFIRMED → PUBLISHED → RETIRED

Evidence Store / PII Vault

  • 简历、消息、录音、附件只存 evidence_ref
  • TTL、访问审计、candidate data key、删除与 crypto-shredding
▼

⑤ 数据源与连接器层

首次全量 + 增量游标/Webhook + 定期对账；对账结果也走事件管道

TTC CRM

  • 职位、HC、招聘状态和权威 job_id
  • snapshot freshness / completeness gate

飞书与招聘网站

  • message_id、thread/card context、external candidate id
  • 正文/联系方式进 Evidence Store，不进事件 payload

worker_events 瞬态 relay

  • worker→API→SSE，1h GC，启动不回放
  • 禁止作为历史账本、统计源或业务回放来源

三座桥 = 三组 Saga

桥 1 上线前门禁：先完成 envelope、entity_links、Case 状态机、消费者幂等、upcaster/DLQ，并用 fixtures 回放成功、失败、超时、重复、乱序和补偿。施工窗口 9/3–9/4 不等于跳过门禁。
桥 1 · 接单 → 建岗job.accepted → position.create_requested → created | failed | timed_out
成功写 project_id ↔ position_id；释放后发 close_requested 补偿。
桥 2 · Case → 审核 → 推人candidates.ready → case.created → draft → consent → approved → sent
9/8 目标；送达失败用 bounced，不能混为无回应。
桥 3 · 结果 → 下一轮interaction.resulted → case/project projection → followup | retry | conversion
前置修 BUG-101/103；采用事件投影，禁止同步双写两库。
首日指标：source freshness、event lag、DLQ depth、case SLA violations、saga stuck count。
不可逆边界：错合并可拆分；阶段回退只发 correction；旧事件只 upcast 不改写；未确认知识不自动执行。
