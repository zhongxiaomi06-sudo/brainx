# 034 Plan — 事件投影运营看板

## 实现顺序

1. 新增能在旧结构上失败的测试，冻结迁移表、幂等/乱序/更正/重建、口径、追溯与管理员权限。
2. 新增 `0059` 归一事件流、checkpoint、实体读模型、快照、投影运行和备份证据；以触发器捕获后续状态变化并幂等回填历史事实。
3. 新增独立消费者与聚合器；worker 定时消费，管理员可显式触发增量或重建，GET 只读取快照。
4. 新增独立 admin route factory，避免继续扩张 `server.js`；事件抽样只返回脱敏信封。
5. 在设置中心接入管理员专属运营看板组件和 Storybook 场景，同步五状态审核文档。
6. 创建中文原子实现提交，在该提交上跑完整门禁，再记录验证提交。

## 不做

- 不连接生产数据库，不执行生产迁移、备份或恢复。
- 不把影子结果包装成真实业务效果，不把未知 Token/成本写成 0。
- 不在浏览器直接聚合业务表，不开放任意 SQL、任意租户或任意事件 payload 查询。
- 不增加图表依赖；当前指标规模使用原生 CSS、语义化表格和简洁条形对比。

## 验证

- 后端：迁移、投影增量/重建、重复/乱序/更正、指标拆分、追溯和 HTTP 权限。
- 前端：数据适配、加载/空/失败/陈旧、LIVE/SHADOW 分栏和窄屏 Storybook。
- 仓库：`npm run verify:quick`，实现提交后 `npm run verify`。
