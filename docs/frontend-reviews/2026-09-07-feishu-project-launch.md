# 2026-09-07 飞书寻访启动入口正式接入记录

> 上级入口：[前端审核台账](README.md)

## 审核范围与用户决定

- 用户明确要求把“职位加入我的项目后，在飞书拉群、投放职位、机器人自动找人并回传候选人”作为当前第一优先级。
- 本轮范围是正式“我的项目”中的启动入口与状态反馈，不改变“加入我的项目”的轻量归属语义。
- 用户尚未审核本轮最终视觉，因此中央台账继续保持“退回修改”，不得把代码接入等同于视觉通过或目标环境发布。

## 正式入口和真实动作

- 待开始项目的主按钮为“在飞书启动寻访”。点击本身构成本次明确确认，不再弹出目标、第一行动和截止时间表单。
- 前端先读取 `GET /api/v1/opportunities/:id/launch`；存在身份、凭证、生产地址或权限缺项时，汇总显示真实阻断原因。
- 预检通过后调用 `POST /api/v1/opportunities/:id/launch`，后端负责建群、投放职位、接单和启动 OpenMai；前端不猜测步骤成功。
- 项目摘要读取持久 launch 状态，展示创建中、OpenMai 找人中、候选人已回群和失败重试。

## 验收边界

- 自动验证必须覆盖待开始按钮、真实 API 调用标识、加载禁用、找人中禁用和失败可重试。
- 已在本机 Storybook 浏览器中目视核对“待开始”和“OpenMai 找人中”场景：按钮文案、禁用态、状态文案和项目卡片布局正常；这仅是实现验收，不替代用户视觉审核。
- 目标环境仍需用真实顾问和真实职位验证：飞书权限预检、只创建一个群、机器人在群、职位卡可见、OpenMai 状态刷新及候选人回群。
- 未完成真实租户验收前，目标环境发布保持“未发布”，真实数据验证保持“部分验证”。
