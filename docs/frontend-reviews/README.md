# 前端审核台账

> 上级入口：[BrainX 文档书](../README.md)
>
> 仓库级规则：[多 Agent 协作准则](../../AGENTS.md#9-前端审核状态同步)

本台账是 BrainX 前端审核状态的唯一权威。它用于回答五个不同问题：Storybook 是否完成、用户是否审核、正式应用是否接入、目标环境是否发布、真实数据是否验证。其他文档可以解释设计或施工细节，但不得自行给出与本台账冲突的完成状态。

## 状态定义

| 维度 | 允许状态 | 完成证据 |
|---|---|---|
| Storybook | 未开始、制作中、待审核、已完成 | 真实生产组件 story、边界场景和交互测试 |
| 用户审核 | 未审核、部分通过、已通过、退回修改、暂停 | 带日期和明确范围的审核记录 |
| 正式接入 | 未接入、部分接入、已接入 | 正式入口的 import、路由、真实动作和接口映射 |
| 目标环境发布 | 未发布、待确认、已发布 | 目标环境、版本或 commit 和发布时间 |
| 真实数据验证 | 未验证、部分验证、已验证、验证失败 | 真实接口、字段、数量、空值、异常路径和关键动作证据 |

“已完成”只适用于单一维度。只有五个维度分别满足验收，组件或页面才可以在施工清单中标记为整体完成。

## 每次审核的强制流程

1. 审核前在 Storybook 准备默认、空值、异常、窄屏和关键交互场景，并记录对应 commit。
2. 用户确认后，在本目录新增 `YYYY-MM-DD-主题.md`；同一天同主题有多轮时追加简短后缀。
3. 审核记录必须区分“确认了什么”和“没有确认什么”，并明确是否授权接入正式应用。
4. 正式接入时核对所有入口是否真正复用审核组件，并记录真实字段、接口、动作和仍缺失的后端契约。
5. 发布时补充目标环境和版本证据；未核验目标环境时只能写“待确认”。
6. 真实数据验证后补充成功、空值、异常和关键动作结果；任何失败都必须退回对应状态。
7. 同步更新本台账、审核记录、[施工清单](../frontend-refactor-construction-checklist.md)和[Storybook 说明](../storybook-component-library.md)，再提交一个独立中文 commit。

## 维护边界

- 单次审核记录保存历史事实；后续不得把原本“未确认”静默改成“已确认”，应追加带日期的状态更新。
- 施工清单负责可执行任务，不负责重新定义审核状态。
- Storybook 文档负责组件使用和技术边界，不负责推断发布状态。
- Commit 日志只记录本次改动，不代替审核记录或中央台账。
