## 1. 目标

建立与 `baseline-1.1` 分离、默认关闭的 `agentic-ranking-v1` 最小链路：硬资格过滤、多路召回、覆盖清单、授权补查、Agent 最终有序列表、稳定校验与 generation/CAS 原子发布。本阶段只落新 A 运行账本，不切换正式 Web/飞书读路径。

## 2. 行为要求

### S1｜硬过滤与多路召回

服务端在 Agent 前处理可见性、完整快照、在招状态、明确排除/忽略、已承接、容量上限和硬冲突。召回合并明确方向、历史相似、近期需求、供给和探索通道；召回分只是候选元数据，不决定最终顺序。

### S2｜冻结输入与 Agent 最终决定

运行冻结租户/顾问、generation、时点、来源水位、画像/信号/负载/权限版本、职位事实版本、候选集、覆盖清单、上下文/模型/prompt/工具/策略和预算版本。所有最终推荐及名次由 Agent 一次最终输出决定；校验器不打分、不重排、不用基线补齐。

### S3｜校验、修复、弃权与失败

严格校验 schema、run 身份、数量、唯一连续 rank、候选资格、职位版本和本轮证据引用。最多修复 2 次且计入预算；无最终 JSON、伪证据、非法/重复职位、取消或超预算不发布。合法弃权和不足 20 条均如实保存。

### S4｜发布临界区

模型调用不占数据库事务。发布短事务内重校验 generation、权限、画像/负载版本、忽略和职位状态；旧 generation 标记 `STALE`，不覆盖新结果。项目顺序原样保存。

### S5｜关闭、回放与兼容

开关默认关闭；关闭时不创建 A run。决策回放只读冻结输入/输出，不再调模型。A 表不进入既有 `COMPLETED` 基线读路径；本阶段不发送、不发布到正式用户。

## 3. 验收

1. 明确排除、忽略、已承接、关闭、越权和容量超限职位不进 Agent 候选。
2. Agent 返回 B、A、C 就按 B、A、C 保存；8 条就只保存 8 条。
3. 无最终输出、伪证据、重复 rank/职位、超预算和取消均不发布。
4. 发布前忽略/撤权/关闭或两个 run 乱序完成时，旧输出标记 `STALE`。
5. 弃权、失败和发布用量可回放；没有 A 输出就没有 A 推荐。
6. 专项、快速和完整门禁通过。
