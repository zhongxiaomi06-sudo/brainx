# 找人链路产品形态设定（2026-10-09）

> 上级目录：[BrainX 文档书](README.md)
>
> 适用场景：找人链路（四条通道）的交互形态、渠道分工与群聊展示的**唯一权威设定**。
> 验证方法：逐条对照「动作 → 效果」表验收；卡片改动过 [卡片渲染回归门禁](2026-09-12-feishu-card-render-gate.md)。

## 1. 元决策（2026-10-09 拍板）

- **群卡片 = 找人动作的即时交付面；工作台 = 资产沉淀与回溯面。** 两条链路分工，不二选一。
- **Sourcing.app（本地软件）走路线 B**：BrainX 不直连顾问本机 harness，只消费成果——撞库命中的候选人经同步入人才库，群结果卡标注来源。
- **群消息的客户诉求提炼由 BrainX judgment-extract 主导**，Sourcing 消费其产出，两个 AI 不在同一个群各说各话。
- 隐私纪律：撞库来的手机号**只私发发起人**，群里只标状态（有电话 ✓ / 无）。

## 2. 渠道分工（四通道）

| 通道 | 形态 | 顾问何时用 |
|---|---|---|
| 内部人才库（Reloop） | 预计算短名单，即时 | 任何找人先过这道（零成本） |
| OpenMai 按职位 | 云端引擎，3-5 分钟 | 有已接单职位 |
| SuperMai 按判据 | 云端引擎，自由判据 | 无职位、按方向找人 |
| Sourcing.app | 本机持续采集 + 撞库电话（路线 B：只消费成果） | 批量扩池、要手机号 |

## 3. 逐步交互设定（动作 → 效果）

### 发起

| 动作 | 效果 |
|---|---|
| 点职位卡 [OpenMai/SuperMai 找人] | 2 秒内回声卡「正在处理…3-5 分钟」，确定性直调不依赖模型 |
| 点 [按条件找人] / 发「找人条件：…」 | 条件登记；下一张找人卡顶部小字回声「本轮条件：…」 |
| 群里 @ 贴整段 JD | 复述字段卡「公司·职位·城市·HC [确认建岗]」→ 确认后一步建岗 |
| 群监听识别到新需求 | 需求识别卡「听到你们在聊 XX [按此找人] [记下来]」 |

### 等待与终态（所有结局必到群）

| 动作 | 效果 |
|---|---|
| 任务完成 | 结果卡：判据摘要行 + 轮次行（首轮/续搜·已排除 N 人）+ 候选人列表 |
| 需要补充信息 | 橙卡「请补充职位信息」+ [补充条件] 输入框，填完直接重触发 |
| 失败/中断 | 红卡如实写明原因；问进度如实回答，不静默重跑扣费 |
| 零命中 | 「未搜到」卡 + [按建议放宽重搜]（系统预填放宽版判据） |
| Sourcing 渠道进行中 | 轮次播报卡：「第 N 轮：新入库 X 人、撞库命中电话 Y 人、下一轮动作：…」 |

### 候选人动作（每行候选人，秒级回执）

| 动作 | 效果 |
|---|---|
| 点姓名 | 打开 TTC 人才详情 |
| [初筛通过] | 回执「已初筛通过」+ 项目群发 TTC 链接 + 进项目重点名单 |
| [加入 reloop] | 回执「已加入人才库 / 已在库 / 同步中」 |
| [不合适] | 二次确认 → 落负反馈 → 下一轮自动排除（越找越准） |
| [查联系方式] | 有撞库电话 → 私发发起人；无 → 回执「待撞库」 |

### 参数微调

| 动作 | 效果 |
|---|---|
| 群里发「找人条件：…」 | 当轮补充条件，不覆盖权威判据 |
| 工作台抽屉判据编辑框 | 编辑权威判据（search_brief），保存后全渠道下一次找人生效 |

## 4. 验收口径

- 发起 → 回声 < 2 秒；四种终态 100% 有卡到群；
- 结果卡：判据可见、轮次/排除数可见、每候选四动作且各有回执；
- 微调：权威判据只有一个编辑处（工作台），群内只做当轮追加；
- Sourcing 成果：撞库候选人入库后能在群结果卡出现且标注来源。

## 5. 实施顺序（已拍板部分先行）

1. ✅ 已完成（2026-10-09）：四种终态到群（needs_input 投递/终态读回/僵尸 running）、群贴 JD 建岗、SuperMai 群发卡；
2. 下一步：结果卡加判据摘要/轮次行、[不合适] 负反馈按钮、needs_input 橙卡 [补充条件] 输入框；
3. 再次：工作台判据编辑框、需求识别卡主动通知、Sourcing 成果同步入库与来源标注。
