# 职位详情放大与固定操作区复审记录

[返回前端审核台账](README.md) · [返回文档总目录](../README.md)

## 审核身份

- 审核日期：2026-08-31
- Storybook 场景：`业务组件/居中职位事实卡审核稿/从全部职位打开并隐藏`
- 对应 commit：本次 `fix(detail): 放大详情并固定底部操作`
- 审核范围：统一职位详情的整体尺寸、五个栏目切换边界，以及已加入项目的忽略入口。

## 用户结论

- 已确认：此前 820×400 的桌面卡片过扁、内容展示不足；卡片应整体放大。
- 已确认：切换职位事实、判断、跟进与结果、决策轨迹、回放时，只允许中间内容变化，卡片框架和底部按钮必须完全一致。
- 已确认：已加入且允许移除的项目，应在“已加入我的项目”左侧显示“忽略”，点击后复用现有移除逻辑并立即从项目中去掉。
- 未确认：目标环境最终视觉和真实项目删除动作。
- 正式接入授权：允许直接修改已接入的统一 `JobDetailCard` 和现有 membership 移除边界。

## 实现与边界

- 桌面详情外框由 820×400 放大为 960×600；标题、事实标签、页签和底部操作区属于固定框架，只有中间内容区滚动和替换。
- 底部操作不再依赖当前页签。相同职位状态下切换任一页签，按钮集合、顺序和尺寸保持不变。
- 已加入且仍可安全移除的项目显示“忽略｜已加入我的项目”；“忽略”复用现有关闭 membership 的动作，成功后刷新项目摘要并移出“我的项目”。
- 允许直接移除待开始，以及尚未进入跟进闭环的 `NEW / RECOMMENDED / VIEWED / DISMISSED / RELEASED / EXPIRED` 归属；已有关注、承接或跟进行动的项目继续拒绝删除，避免行动断链。

## 状态证据

- 正式入口：精选盘、全部职位和我的项目详情继续复用同一个生产组件及同一忽略领域动作。
- 发布环境与版本：未发布。
- 自动验证：Storybook 逐一切换五个栏目，断言桌面弹窗至少 900×560、宽高不变且底部按钮文本不变；加入项目后显示“忽略｜已加入我的项目”，执行忽略后恢复“加入我的项目”。membership HTTP 测试覆盖可移除状态和跟进态 409 保护。
- 本地浏览器验证：在正式“我的项目”打开待开始项目，五个栏目均保持同一位置和 605.21px 高度；受当前窄浏览器窗宽限制，宽度为 514.62px。每个栏目底栏都严格保持“忽略｜已加入我的项目”。为避免改写用户真实项目，本轮未在浏览器点击“忽略”。
- 真实数据验证：已用本地真实项目只读验证按钮条件和页签稳定性；目标环境写入动作仍待发布后确认。
