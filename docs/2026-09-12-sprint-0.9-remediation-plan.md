## 5. 执行顺序与提交切分

按原子 commit 逐个提交，每个 commit 独立可回滚：

```
1. fix(frontend): OpenMai 按钮文案收尾 + 一键启动项目改名 + 删除不可达 accept 表单   (R2/R3)
2. fix(agent):    人才库幂等查重去 LIKE 通配 + 回归用例                              (R5)
3. feat(frontend): OpenMai 推荐字段内联编辑态                                       (R6)
4. docs(sprint):  处置结论回填（清单 + 前端台账 + 审核记录 + 演示脚本 + 提交日志）    (R1/R7/R8/R9)
5. (仅在 R1 选② 时) feat(feishu): 卡片回执后置更新为「已收藏」                       (R1②)
```

约束：

- `workbench.tsx`（499）、`engagement-loop.tsx`（496）**只能等行替换或净减行**，不得跨过 500。
- 前端改动同步更新 Storybook 场景与断言（`app/stories/*.stories.tsx`）。
- 每步先跑 `npm run verify:quick`，push 前跑完整 `CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run verify`，要求 24/24、failed=0、`latest.md` 结论为「通过」。
- 前端审核台账按 AGENTS.md §9 五维同步，不得只改代码不改台账。
