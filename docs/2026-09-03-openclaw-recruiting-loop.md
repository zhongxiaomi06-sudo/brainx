# OpenClaw 招聘闭环（2026-09-03）

> 上级入口：[BrainX 文档书](README.md)
> 原始设计：[OpenClaw AI 招聘工作流 PRD](prd-2026-09-02-openclaw-ai-recruiting-workflow.md)

## 本轮用户决策

用户明确要求从“只读建议”升级为可执行的最短业务闭环，并确认自动建群后置。本文件是对 2026-09-02 PRD“首版只读”限制的后续产品决策；身份绑定、对象可见性、独立人才授权、确认、幂等和审计边界继续保留。

## 已接通链路

1. 所有 OpenClaw 飞书最终回答由受版本控制的适配器包装为结构化卡片；已有卡片不重复包装。
2. 顾问可用自然语言设置每天 1—4 个时间、每次 1—10 个职位；机器人复述并确认后保存。
3. 推荐卡按设置数量展示，每个职位包含结论、最多两条依据、最多两条风险和一个下一步，并深链到正式工作台。
4. 私聊可读取授权职位负责人；不向模型暴露职位群 `chat_id`。
5. 用户确认后，机器人可接单、建立首条行动并启动 OpenMai 找人，也可记录进展和下一行动。
6. 授权候选人可依次进入：加入项目、准备联系、已发送、已回复、提交客户、面试。机器人与后续工作台接口共用 `consultant_candidate_cases` 状态。
7. 候选联系方式仅在本人私聊、提供业务理由且存在 `scope=contact`、`purpose=candidate_contact` 的独立有效授权时返回。

## 尚未伪装为已完成的能力

- 对外发送联系话术：当前没有稳定的候选外部联系渠道连接器。机器人可以生成话术；只有外部渠道真实成功后才能记录 `RECORD_OUTREACH_SENT`。
- 自动建群：按用户决定后置。
- 工作台候选 Case 专页：底层状态已可共享，现有深链先打开职位详情并预填候选分析；专门的可视化操作区仍待后续前端审核。
- 目标环境发布和飞书真机验证：本轮只完成代码与自动化验证，不能据本地结果声称已发布。

## 工具确认规则

`brainx_update_push_preferences`、`brainx_accept_job`、`brainx_start_candidate_search`、`brainx_record_job_progress` 和 `brainx_candidate_workflow` 都要求本次调用携带明确的 `confirm=true`。模型必须先复述对象和动作；历史消息中的泛化同意不能替代本次确认。
