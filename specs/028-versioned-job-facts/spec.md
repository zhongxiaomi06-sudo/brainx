# 028 — 来源适配与版本化职位事实

状态：Specified（2026-09-23）

上游：[仓库重构施工总手册](../../docs/2026-09-22-refactor-agentic-ranking-manual.md)阶段 04、
[推荐重构数据契约](../../docs/2026-09-22-ranking-data-migration.md)、
[群消息职位事实提炼路径](../../docs/2026-09-02-job-facts-extraction-roadmap.md)。

## 1. 目标与现状

现有 TTC、fixture、CSV 和已确认群消息/JD 最终都写入 `job_facts`，但来源批次仍使用不同形状，当前投影会覆盖历史，字段证据不能按事实版本查询。重复消息由事件 ID 去重，却不能复用同一授权范围内相同正文的提炼结果；来源冲突和投影漂移也缺少可复核记录。

本单元在不切换生产读路径的前提下，建立统一来源信封、不可变事实版本、字段证据、提炼缓存和只读优先的投影对账/补偿。`job_facts` 继续作为兼容当前投影，现有 `project_id`、membership、群与 Case 引用保持不变。

## 2. 行为要求

### S1｜统一来源信封

TTC 与本地 CSV/fixture 必须产出同一来源信封：来源实例、适配器/契约版本、批次、作用域、游标、完整性、接收时间、记录及错误。旧 `payload.jobs` 入口继续兼容，但在写入前必须被规范化；缺页或失败不能产生 tombstone、关闭缺失职位或推进“完整快照”语义。

### S2｜不可变版本与字段证据

每次规范事实发生变化时追加 `job_fact_versions`；内容未变不增加版本。每个来源记录以租户、来源实例、实体类型和外部 ID 唯一登记；字段证据绑定事实版本，区分来源事实、人工确认与软推断。TTC 原字段只允许存在于适配/证据边界，下游继续读取规范字段。

### S3｜草稿确认与提炼缓存

群消息和 JD 继续只产待确认草稿；未经确认的模型/规则结果不得写入权威投影。相同租户和授权范围内，正文哈希、提炼 schema、模型/prompt 版本相同的内容复用提炼缓存，不重复调用模型；跨人、跨群或授权范围不同不得共享。软推断不能单独把权限、归属、状态或 HC 提升为已确认硬事实。

### S4｜单写入口、冲突与对账

`job_facts` 的来源同步和草稿确认写入必须经同一个职位事实写模块。写入当前投影、版本、来源映射和证据处于同一 SQLite 事务；不同来源对同一字段给出不同值时必须记录冲突，不能静默丢失任一版本。提供只读对账和显式补偿入口，默认 dry-run；补偿只恢复规范事实投影，不重编号或改写 membership、群、Case 与历史版本。

### S5｜兼容与安全

保持现有同步返回、推荐资格、路由、CLI、草稿可见性、人工确认和 `baseline-1.1` 行为。不得新增依赖、连接生产、执行生产迁移/回填、切换正式读取、发布或 push。

## 3. 验收

1. 同一规范事实分别经 TTC 和本地 CSV/fixture 输入时，得到等价的规范内容；下游测试不读取 TTC 原字段。
2. 同内容重复同步只更新来源观察信息，不增加事实版本；内容变化追加版本与逐字段证据。
3. 相同作用域同正文只调用一次提炼器；跨作用域不复用；确认前 `job_facts` 不变化。
4. 来源冲突可查询；投影漂移可 dry-run 检出并显式修复，引用 ID 全部稳定。
5. TTC 分页中断/不完整信封不关闭缺页职位、不写 tombstone，且完整水位不被伪装推进。
6. 专项回归、快速门禁及最新提交完整门禁通过，质量报告 Push 条件满足。
