# Feature Specification: OpenClaw 多顾问生产化

**Feature Branch**: `codex/feishu-agent-prd-20260901`

**Created**: 2026-09-03

**Status**: Approved（用户已授权完成当前 PRD 的三个优先级、部署、推送并创建 PR）

**Input**: 把已验证的 Mia 单人本机 PoC 建设为服务端常驻、无需顾问本机安装 OpenClaw、可由白名单顾问在飞书私聊或白名单群安全使用的 AI 猎头工作流；完成身份权限、人才数据、匹配解释、审计、恢复和公开 HTTPS 深链，并逐任务验收。

**Authority**: [BrainX × OpenClaw AI 猎头工作流 PRD](../../docs/prd-2026-09-02-openclaw-ai-recruiting-workflow.md)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 顾问在任意设备安全对话（Priority: P1）

已登记顾问无需在自己的电脑安装 OpenClaw，只需在飞书私聊机器人，或在白名单群里 @ 机器人，就能读取本人有权查看的职位和人才信息。系统从飞书事件身份识别顾问，消息正文中的身份声明不能改变权限。

**Why this priority**: 这是把本机 PoC 变成可推广产品的前提，也是跨顾问数据隔离的安全底线。

**Independent Test**: 使用两名顾问、两个群和同一个职位编号回放请求，验证每人只看到自己的授权对象；伪造顾问或租户参数无效；未绑定用户和未登记群得到统一拒绝。

**Acceptance Scenarios**:

1. **Given** 已绑定的白名单顾问从飞书私聊发问，**When** 请求本人今日工作，**Then** 返回本人可见数据、数据时间和证据，不要求本机安装任何软件。
2. **Given** 两名顾问询问同一个对象编号，**When** 只有一人拥有权限，**Then** 有权限者得到裁剪结果，另一人得到不泄露对象是否存在的统一拒绝。
3. **Given** 消息正文伪造顾问、租户、sender 或 scope，**When** Agent 调用数据能力，**Then** 系统只采用渠道提供的可信身份，伪造字段被拒绝或忽略并被审计。
4. **Given** 白名单群内的合法 @ 请求，**When** 返回候选人信息，**Then** 只显示脱敏候选概况；私聊和群聊上下文互不串线。
5. **Given** 未绑定用户、未登记群或机器人消息触发请求，**Then** 请求不进入业务数据读取路径。

---

### User Story 2 - 顾问完成猎头黄金工作流（Priority: P1）

顾问能在一次连续飞书会话中完成“今日简报 → 职位判断 → shortlist → 候选人证据 → 沟通草稿”，回答使用猎头能快速判断的语言，且首期不执行任何业务写入或外发。

**Why this priority**: 只有完整闭环才能验证产品是否真正辅助顾问变强，而不只是数据查询机器人。

**Independent Test**: 用一份已授权的真实脱敏职位—候选人数据回放五步工作流，验证每一步都能单独完成、连续追问不丢对象、结论均有证据或明确标为未知。

**Acceptance Scenarios**:

1. **Given** 顾问问“我今天先做什么”，**Then** 返回最多 5 项优先动作，每项说明事实、为什么现在做、建议和待确认。
2. **Given** 顾问询问一个可见职位，**Then** 返回职位事实、独立的投资判断、风险和最关键缺口，不自动承接职位。
3. **Given** 职位存在已完成且仍获授权的匹配版本，**Then** 私聊最多显示 Top 5、群聊最多显示脱敏 Top 3，并将候选人实力与本职位匹配分开说明。
4. **Given** 顾问追问某候选人，**Then** 返回可追溯事实、证据、最大风险和一个最有价值的问题；没有证据的内容不得写成事实。
5. **Given** 顾问要求沟通话术或面试准备，**Then** 只生成草稿，不发送消息、不写评价、不虚构薪资、汇报线或经历。
6. **Given** 没有可用版本、数据过期或依赖不可用，**Then** 明确说明原因，不临时扫描全库、不使用内存假数据。

---

### User Story 3 - 授权人才被持续盘活（Priority: P2）

系统持续同步每位顾问已共享或获授权的人才数据，将结构化来源或数字 PDF/DOCX 转换为有版本、有证据、有质量状态的候选人事实，再生成可解释、可复跑的匹配结果。

**Why this priority**: 单职位手工 Top10 不能支撑日常工作；规模化之前必须先保证授权、事实和删除传播正确。

**Independent Test**: 对增量结构化档案、数字 PDF、空文本扫描件、恶意提示文档、重复数据和撤权事件进行回放，验证版本、证据、幂等、质量状态和撤权传播。

**Acceptance Scenarios**:

1. **Given** 某顾问拥有有效人才授权，**When** 增量同步运行，**Then** 只处理游标之后的变化，并产生不可变事实版本和证据引用。
2. **Given** 数字 PDF 或 DOCX，**When** 解析成功，**Then** 所有结构化输出通过固定 schema；关键事实无证据时不能标为已支持。
3. **Given** 扫描件或无可提取文本文件，**Then** 标为 `OCR_REQUIRED`，不生成看似完整的事实。
4. **Given** 文档中包含要求改变系统规则的文字，**Then** 文字只被当作简历内容，不能扩大工具或数据权限。
5. **Given** 授权被撤销，**When** 撤权传播完成，**Then** 列表、详情、缓存、索引和会话中的后续读取均不可再获得该人才。
6. **Given** 新匹配特征尚未通过固定评测，**Then** 只记录影子结果，不改变正式 shortlist 顺序。

### User Story 4 - 管理员可部署、审计和恢复（Priority: P1）

管理员能把 BrainX、OpenClaw 和飞书插件部署为服务器常驻服务；顾问通过飞书和受保护的 HTTPS BrainX 页面使用，管理员能验证实际工具权限、查看脱敏审计、轮换密钥并从重启或重复事件中恢复。

**Why this priority**: “任何电脑可用”依赖服务端常驻和稳定域名，而不是复制开发者本机环境。

**Independent Test**: 在干净环境按部署文档安装发布包，执行健康检查、插件运行时检查、安全审计、重启、重复请求和公开深链登录测试。

**Acceptance Scenarios**:

1. **Given** 一台符合要求的服务器和环境凭据，**When** 管理员按文档部署，**Then** 两个服务以非公开内部连接协作，重启后自动恢复，密钥不进入仓库、镜像或日志。
2. **Given** 顾问在手机或另一台电脑点击飞书卡片，**Then** 打开稳定 HTTPS 页面并重新校验其登录身份和对象权限。
3. **Given** 管理员检查生产 Agent，**Then** 实际工具清单只包含批准的只读/计算工具，不包含 Shell、文件、任意网络、SQL 或业务写工具。
4. **Given** 相同事件或主体声明被重复发送，**Then** 不产生重复结果；过期、篡改和重放请求被拒绝并记录。
5. **Given** OpenClaw、BrainX 或长任务进程重启，**Then** 已受理任务可继续、可查询或明确失败，不永久停留在运行中。
6. **Given** 一次 Agent 回答，**Then** 管理员可通过 request/run 标识关联身份解析、授权结果、工具版本、数据版本、模型版本、拒绝或错误，不记录完整简历和密钥。

### Edge Cases

- 飞书 App 更换后 `open_id` 改变：必须按 App 维度重新绑定，不能复用旧 App 标识。
- 插件缺少 sender、channel 或 account 上下文：工具必须拒绝，不能回退到 Mia 或默认顾问。
- 群已登记但发言人未获准：渠道层拒绝，不调用模型和业务工具。
- 对象存在但用户无权查看：与对象不存在返回相同错误。
- 数据库、模型、飞书或外部搜索部分失败：返回明确状态和可重试性，不拼接过期结果冒充成功。
- 分页期间匹配版本变化：后续页继续读取首屏锁定版本，避免重复或漏人。
- 候选人姓名、手机号、邮箱出现在证据文本：进入群聊投影前必须服务端脱敏。
- 深链被转发给无权限用户：页面重新鉴权并拒绝，URL 本身不构成权限。
- 配额耗尽或达到调用上限：停止新增长任务，已完成事实仍可只读查询。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 让顾问只通过飞书或 HTTPS 页面使用服务端 Agent，不要求顾问本机安装 OpenClaw、BrainX 或数据库客户端。
- **FR-002**: 系统 MUST 使用飞书渠道运行时提供的 App、sender、chat、thread 上下文解析顾问和租户，身份字段不得来自模型参数或消息正文。
- **FR-003**: 系统 MUST 支持 App 维度、可验证、可撤销的顾问身份绑定；缺失、冲突、过期或撤销绑定一律拒绝。
- **FR-004**: 系统 MUST 支持白名单私聊发言人和白名单群；群内必须 @ 触发，机器人消息不得触发，私聊和群话题按发言人隔离。
- **FR-005**: 每次业务工具调用 MUST 校验租户、顾问、项目/职位、人才授权、用途和会话类型，并在返回前执行字段裁剪。
- **FR-006**: 生产 Agent MUST 只拥有 PRD 批准的只读/计算工具；SQL、Shell、文件系统、任意网络、配置写回、动态 Agent 和业务写工具均不可用。
- **FR-007**: 系统 MUST 提供今日简报、职位判断、候选 shortlist、候选事实、职位匹配、缺口问题、面试准备、个人复盘和长任务状态读取能力。
- **FR-008**: 所有工具 MUST 返回一致的版本化结果，区分事实、推断、建议和未知项，并包含数据范围、证据、数据/算法版本、生成时间和允许的下一步。
- **FR-009**: 群聊投影 MUST 隐藏联系方式、完整简历、薪资隐私、私人评价和其他项目反馈；私聊也只返回当前用途所需字段。
- **FR-010**: 系统 MUST 使用不可变请求标识、短时主体声明、请求体摘要和一次性 nonce 防止篡改与重放；验签失败不得执行领域函数。
- **FR-011**: 系统 MUST 记录脱敏的 Agent 请求、身份映射、授权结果、Skill/工具/模型/数据版本、耗时、拒绝和结果状态，并可通过 request/run 标识关联。
- **FR-012**: 系统 MUST 提供人才授权、文档、事实版本、证据、职位条件、匹配运行、匹配结果和同步游标的持续迁移与查询能力。
- **FR-013**: 系统 MUST 对结构化档案和数字 PDF/DOCX 进行隔离解析，校验固定 schema、记录来源 hash 和证据；扫描件必须返回 `OCR_REQUIRED`。
- **FR-014**: 系统 MUST 使用增量游标和幂等键同步授权人才，不得每天无条件全量复制；撤权后缓存、索引和查询投影必须失效。
- **FR-015**: 系统 MUST 将候选人实力、本职位匹配、硬条件、证据覆盖和风险分别建模；新增排序只有在固定真实评测集签署通过后才能替换现有顺序。
- **FR-016**: 系统 MUST 为解析、搜索和大批量匹配提供持久任务状态、费用/次数上限、超时、取消、重复回调处理和重启恢复。
- **FR-017**: 飞书卡片 MUST 使用受版本控制的模板，最多展示当前场景允许的对象数；详情按钮指向稳定 HTTPS 对象深链并在页面端重新鉴权。
- **FR-018**: 系统 MUST 在依赖不可用、授权不足、数据过期或质量不足时诚实失败，不使用内存假数据、未授权旧缓存或模型猜测替代。
- **FR-019**: 系统 MUST 提供可复现的安装包、环境模板、进程托管、健康检查、备份恢复、密钥轮换和发布回滚说明，且不包含真实凭据。
- **FR-020**: 发布前 MUST 通过跨用户、跨租户、跨项目、群/私聊、字段投影、提示注入、幂等重放、重启恢复和实际工具枚举测试。
- **FR-021**: 首期 MUST 保持业务只读；沟通文案、面试准备和个人建议只作为草稿，不自动发送、不改变项目、人才或招聘流程状态。

### Key Entities

- **Feishu Identity Binding**: 飞书 App 维度的顾问身份绑定及撤销状态。
- **Agent Group Scope**: 白名单群、允许发言人、会话用途和数据范围。
- **Agent Run / Tool Call**: 一次用户请求及其工具调用的脱敏审计链。
- **Principal Assertion / Nonce**: 由可信渠道上下文形成的短时主体声明及防重放记录。
- **Talent Access Grant**: 人才在顾问、项目或团队服务账号范围内的用途和字段授权。
- **Candidate Document / Fact Version / Evidence**: 原始来源引用、不可变候选人事实版本和逐字段证据。
- **Job Criteria Version**: 职位必需、优先、职责和待确认条件的版本。
- **Match Run / Candidate Job Match**: 不可变匹配运行和候选人解释结果。
- **Integration Job / Outbox**: 可恢复长任务和原会话结果通知。
- **Source Sync Cursor**: 每个租户、数据源和对象类型的增量同步位置。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 3 名白名单顾问分别在两种不同设备上完成飞书私聊使用，客户端设备无需安装 OpenClaw 或 BrainX。
- **SC-002**: 跨顾问、跨租户、跨项目、未登记群、未授权发言人和深链转发负向测试的数据泄漏数为 0。
- **SC-003**: 100% Agent 业务工具调用能关联到唯一 request/run、身份绑定、授权判定、工具版本和数据版本。
- **SC-004**: 100% 群聊候选人回复不包含手机号、邮箱、完整简历、薪资隐私或私人评价。
- **SC-005**: 灰度顾问能在 5 分钟内完成“今日简报 → 职位判断 → shortlist → 候选人证据 → 沟通草稿”闭环，过程中无业务写入。
- **SC-006**: 数字 PDF/DOCX 解析结果 100% 通过 schema；所有被标为已支持的关键事实都有可回溯证据；空文本扫描件 100% 返回 `OCR_REQUIRED`。
- **SC-007**: 相同事件、请求和任务回调重复执行不产生重复业务结果或重复通知。
- **SC-008**: 服务和 worker 重启后，不存在永久停留在 `RUNNING` 且不可查询、不可恢复或不可明确失败的任务。
- **SC-009**: 生产实际工具枚举与批准白名单完全一致，禁止工具数量为 0；插件、网关和 Skill 中不含真实密钥。
- **SC-010**: 所有飞书卡片详情按钮均打开稳定 HTTPS 页面；未登录或无权限访问得到安全拒绝，本机地址出现次数为 0。
- **SC-011**: 新匹配排序在未完成固定评测和人工签署前影响正式 shortlist 的次数为 0；评测报告可复跑并包含 Recall@20、NDCG@10、硬条件误放率和证据覆盖率。
- **SC-012**: 完整质量门禁通过后才能发布；生产健康检查、插件运行时检查、安全审计和一条真实灰度工作流均留下新鲜证据。

## Assumptions

- “任何人的电脑都能使用”定义为：同一飞书企业中已实名绑定并进入白名单的顾问，可从任意受支持飞书客户端或浏览器使用服务；不等于向公网匿名用户或任意飞书租户开放。
- 首期使用一个生产飞书 App 和一个明确租户；跨租户 SaaS 自助开通、管理员控制台和计费不属于本规格。
- 现有 `https://base.yorkteam.cn` 继续作为 BrainX 正式 HTTPS 入口；OpenClaw 与 Agent Gateway 部署在受控服务器，Gateway 不直接暴露公网。
- DataClaw 没有经验证的正式接口，因此个人复盘缺少其数据时必须明确标注，不阻塞职位与人才闭环。
- 现有 reloop 顺序在评测签署前仍是正式 shortlist 基线；新增解析和匹配只产生版本化证据及影子特征。
- 首期不读取群历史、不下载飞书附件、不写云文档、不建群、不代顾问发送外部联系消息。
- 用户已授权本功能的实现、必要生产部署、推送分支和创建 PR；任何必须由飞书/云服务账号持有人完成的审批仍需平台交互确认。
