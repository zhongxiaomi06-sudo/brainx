## 二、第一版对应结果（85 家活跃客户 × 顾问岗位族）

- **覆盖 52/85（61%）**：客户主岗位族在某顾问 top3 族内 → routed push 可直接路由；
- **33 家「未覆盖」拆开看**：29 家是客户画像「未分类」（词表盲区，非业务真空）——**修正口径后真实覆盖 = 52/56 ≈ 93%**；真正无承接能力的设计 3 家、其他技术 1 家；
- **结构性瓶颈（真实风险）**：客户需求侧管理岗 113 条、市场/增长 101 条，但承接厚度各只有 1 位顾问（管理岗/市场各 1）——**需求第二第三大的族恰恰是人力最薄的**；算法需求 271 条有 8 位顾问可接，供给冗余。

## 三、第一版评估（诚实版）

**能用**：
1. 正向画像（谁爱接什么）信号真实——84 次 ACCEPTED + 339 在任 membership 都是行为事实，不是自报；
2. 对应矩阵路由可用：61%→93% 修正覆盖意味着 routed push 第一版可上线灰测（仅对 main family 命中的 52 家做定向，未命中走原通用推送）；
3. 负载不均已可视化：york 189 在任 vs linda 3——routed push 同时是负载再平衡的依据。

**不能用 / 风险**：
1. **只有正向画像**：feedback 72 条全是 NOT_INTERESTED 但无顾问粒度细分、judgment 14 条无结论——「谁明确不接什么」是空的，路由会误推（比如给 mia 推 BD 单她大概率不接，但画像里没有这条边界）；
2. 29 家未分类客户占「未覆盖」的 88%——**画像词表 v2（top40 并入）落地前，覆盖率数字别对外用**；
3. VIEWED 权重 0.3 是拍的，无点击时长/深度数据支撑；
4. frankie/miya 样本量≈0，她们的画像在第一版里是空壳。

## 四、下一版本径

1. 词表 v2 并入后重算（预期未分类 393 → <150，覆盖数字才可信）；
2. 顾问确认队列产生 confirmed 数据后，把「确认」作为新的正向信号（比 VIEWED 强）补进权重；
3. judgment_drafts 出结论后补负向画像（不接边界）；
4. routed push 灰测范围：先只做 52 家已覆盖客户的定向推送，对照通用推送的 served→viewed→accepted 漏斗。
