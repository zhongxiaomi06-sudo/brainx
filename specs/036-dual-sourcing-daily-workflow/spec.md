## 1. 目标与命名

用户口述中的 “OpenMind / Supermind” 在当前仓库中分别对应 **OpenMai / SuperMai**。本规格以代码内正式名称为准。

本阶段不再把两条链路看成两个孤立工具，而是让它们进入同一个顾问日常循环：

```text
看到职位 → 接单 → 建立/复用项目群 → 补充找人条件
→ 顾问明确选择 OpenMai 或 SuperMai → 立即收到受理状态
→ 后台执行 → 结果回到原项目群 → 关注/回流/继续找人 → 全程留痕
```

## 2. 已验证现状

| 能力 | OpenMai | SuperMai |
|---|---|---|
| 正式入口 | 项目群卡片、Agent 工具 | 项目群卡片、Agent 工具 |
| 执行位置 | 服务端真实 API 链路 | 顾问电脑的桌面 Relay 与官方平台会话 |
| 结果回流 | `openmai_results` → worker → 原项目群 | `sourcing_tasks`/ingest → 兼容投影 → worker → 原项目群 |
| 当前主要缺口 | 仍使用独立结果表和运行态，不在统一任务账本 | 真实异机、真实账号、真实平台结果尚需目标环境验收 |

当前项目群和快捷动作链路已经要求顾问选择找人方式，但 web 接单和 `brainx_accept_job` 仍会默认启动 OpenMai。这个分叉既会造成额外费用，也会让 SuperMai 永远处于次要入口，是本轮首先修复的根因。

## 3. 目标一：两条链路真正进入日常工作流

### 3.1 产品规则

1. 接单只建立承接关系、当前行动和项目群，不自动启动任何找人渠道。
2. 项目群就绪后，顾问必须明确选择 OpenMai 或 SuperMai；禁止静默双跑、静默降级或自动替顾问决定。
3. 两条链路都必须立即返回“已受理 / 正在执行 / 需要登录 / 失败可重试”等可理解状态。
4. 两条链路的结果都回到发起职位的原项目群，不能只停留在工作台或后台表里。
5. 结果卡必须支持关注、暂不考虑、继续找人和进入候选跟进；操作和来源均可回放。
6. 找人条件属于项目事实：同一群内最近一次明确条件用于下一轮，不能跨项目串用。

### 3.2 完成定义

- web、机器人私聊、项目群卡片三个接单入口都不会自动调用付费找人。
- 接单响应显式返回 `awaiting_method`，并提供建群、OpenMai、SuperMai 下一动作。
- OpenMai 与 SuperMai 各完成一次真实账号、真实职位、真实结果回原群的端到端验收。
- 失败路径能告诉顾问下一步是重新授权、启动桌面连接器、重试或换渠道，不出现无限“处理中”。
- 日常提醒能够区分“尚未选择渠道”“任务执行中”“已有结果尚未推进”。

## 4. 目标二：统一任务骨架和运营验收

### 4.1 工程定位

在目标一跑通后，把 OpenMai 从独立 `openmai_results` 运行态迁移到与 SuperMai 共用的任务骨架：

- `sourcing_tasks`：任务、来源、项目、顾问、条件版本、状态和幂等键；
- `sourcing_task_events`：排队、领取、开始、进度、完成、失败、取消；
- 统一候选结果契约：保留来源证据，不强行把不同渠道字段伪装成完全相同；
- 统一重试、取消、超时、费用和耗时观测；
- 找人条件持久化，不依赖单进程内存；
- OpenMai 旧表只作为迁移期兼容投影，消费者逐步切到统一读模型。

### 4.2 完成定义

- 同一个项目的两条渠道任务可在同一账本查看，但不会互相覆盖结果或排除项。
- 服务重启和多实例情况下，找人条件、任务状态和回流目标仍然正确。
- 运营可看到每个渠道的成功率、等待时间、执行时间、失败原因与人工介入点。
- SuperMai 完成真实异机验收；OpenMai 完成统一任务迁移与兼容读回归。
- 发布、真实数据验证与本地代码完成分别留证，不以“代码存在”冒充上线。

## 5. 施工顺序

1. 统一所有接单入口为 `awaiting_method`，删除默认 OpenMai 启动。
2. 回归项目群卡片和 Agent 工具，确认两种渠道都能被明确选择。
3. 用一名真实顾问、一个真实职位分别跑通 OpenMai 和 SuperMai，记录每一步证据。
4. 修复目标环境暴露的登录、连接、回流和错误提示问题。
5. 设计统一任务与结果迁移，先双写/兼容读，再切消费者，最后退役旧运行态。
6. 补齐提醒、运营指标、重试/取消和数据保留策略。

## 6. 不做

- 不自动同时启动两条渠道。
- 不在无明确授权时读取或上传第三方账号密码、验证码、Cookie 或浏览器 profile。
- 不把本地 Storybook、模拟数据或单元测试通过描述成生产可用。
- 不在目标一尚未真实跑通前重写全部数据库或前端。
