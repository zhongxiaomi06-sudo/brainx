# 高频自动推荐与决策轨迹膨胀审计

> 上级入口：[BrainX 文档书](../README.md)
>
> 相关规则：[推荐冻结治理](../db-growth-governance-proposal.md) · [决策轨迹时间顺序复核](../frontend-reviews/2026-08-30-decision-trail-order.md)

## 结论

用户看到的每隔一两分钟一条“已推荐”不是浏览器缓存，而是自动桥接把推荐快照重复写进了 `decision_events`。推荐快照本应只保存在 `decision_runs` 和 `recommendations`；决策轨迹只应展示查看、关注、加入项目、暂不考虑、进展和结果等真实操作。

本轮已修复生成链路并清理本地存量。目标环境尚未发布或清理，不能根据本地结果推断线上已恢复。

## 审计证据

修复前本地 `data/brainx.db` 的只读统计：

| 指标 | 数值 |
|---|---:|
| `decision_events` 总数 | 339,726 |
| 机器 `RECOMMENDED` 事件 | 339,662（99.98%） |
| 真正冻结的 `recommendations` | 4,200 |
| `decision_runs` | 17,079 |
| 有机器推荐记录的顾问/职位组合 | 4,307 |
| 每组合平均机器事件 | 78.9 |
| 单组合最大机器事件 | 2,144 |
| 机器事件时间范围 | 2026-08-26 至 2026-08-30 |

峰值小时出现 9,380 条机器事件，和截图中分钟级连续“已推荐”一致。

## 根因链

1. `startBridge` 默认每 180 秒执行一次；TTC 分页同步会让输入哈希频繁变化。
2. 旧节流只在“哈希未变化且两小时内”生效，分页变化因此绕过节流。
3. 每次推荐把 Top20 再复制成 20 条 `RECOMMENDED` 决策事件。
4. 自动轮即使被跳过或阻断，桥接仍广播“推荐已更新”并触发自动推送钩子。
5. 推荐快照已有最近三轮保留策略，但 `decision_events` 没有对应清理，最终形成大量重复轨迹。

## 修复边界

- 自动推荐改为硬性最小两小时间隔；输入变化留到下一轮基线吸收，人工重算仍可立即执行。
- 推荐继续冻结到 `recommendations`，不再写入 `decision_events`。
- 推荐状态与僵尸轮次改从 `recommendations` 推导，不依赖机器事件。
- 自动轮被节流或阻断时，不再广播“推荐已更新”，也不触发重复推卡。
- 迁移 `0020_remove_recommendation_events.sql` 只删除 `RECOMMENDED`；人工事件完整保留。
- 回放接口防御性排除旧机器事件。

## 本地清理结果

本地迁移后 `RECOMMENDED=0`，保留人工事件 64 条和推荐快照 4,200 条；`PRAGMA integrity_check` 返回 `ok`。离线压缩后主库由 321 MiB 降至 160 MiB，WAL 已截断为 0。该清理不可恢复机器事件，但推荐快照仍在，且机器事件本身不是用户操作证据。
