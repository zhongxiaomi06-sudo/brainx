# 029 — 画像、曝光与结果账本

状态：Implemented，待完整门禁（2026-09-23）

上游：[仓库重构施工总手册](../../docs/2026-09-22-refactor-agentic-ranking-manual.md)阶段 05、
[推荐重构数据契约](../../docs/2026-09-22-ranking-data-migration.md)。

## 1. 目标

在不替换既有项目、推荐和 Case 权威写路径的前提下，把顾问主动画像、短期推断信号、实时项目负载、真实曝光与 Case 业务结果分开版本化。主动画像不被个人模型切换或推断信号覆盖；业务结果只在存在明确决策关联时归因。

## 2. 行为要求

### S1｜主动画像与模型凭据分离

顾问每次修改方向、排除项或容量都追加不可变画像版本，兼容投影继续保存在 `consultants.profile_json`。个人模型凭据及其状态不进入画像版本，切换模型不得改变主动画像版本。

### S2｜短期信号与实时负载

短期信号记录来源、样本数、置信、算法版本、时间窗和到期时间，可撤回且过期后不返回。当前负载每次从项目承接状态和待办计算，不使用画像里的历史计数。

### S3｜真实曝光

冻结推荐项不等于用户已看到。服务端记录 served 和 visible 事件、渠道、位置及幂等键；翻页、重试和同一事件重放不重复累计。

### S4｜Case 结果、更正与归因

候选人推荐、面试、Offer 和 Onboard 从 `workflow_event_log` / Case 权威事件幂等投影到 `job_outcomes`；以租户、来源实例和来源事件 ID 去重。更正事件追加且引用原结果，不改写历史。只有明确 `decision_id` 且顾问/职位匹配时标记已归因，否则保留为未归因业务结果。

### S5｜兼容与安全

复用现有事件账本、消费者幂等和结果表；不新增运行时依赖，不把未知当失败，不连接生产、执行生产迁移/回填、切读、发布或 push。

## 3. 验收

1. 主动画像修改逐版可回放，模型切换不新增或改写画像版本。
2. 过期/撤回信号不进当前上下文；实时负载与项目状态一致。
3. 同一曝光或业务事件重放只记一次。
4. Case 结果、更正和归因可查；无可靠决策关联时不猜测归因。
5. 专项回归、快速门禁和最新提交完整门禁通过。
