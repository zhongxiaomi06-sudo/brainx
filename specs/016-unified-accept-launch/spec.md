# 016 — 三入口统一接单并建群

状态：Implemented（本地，2026-09-11）

> 上级入口：[BrainX 文档书](../../docs/README.md)

## 目标

顾问从每日派单卡、机器人对话推荐卡或工作台任一入口确认一个职位后，都得到同一业务结果：职位进入本人项目、承接状态为 `ACCEPTED`、职位唯一项目群创建或复用、群内出现职位卡。接单本身不替用户选择或消耗找人渠道。

## 用户场景

1. 顾问在私聊说“推荐 5 个岗位”，每个可定位职位都显示“接单并建群”。
2. 点击该按钮即代表本次明确确认；Agent 直接调用 `brainx_accept_job`，不再追问职位编号或确认。
3. 每日派单卡仍以短期签名链接执行同一接单建群工作流。
4. 工作台接单成功后也执行同一项目群工作流。
5. 群建好后顾问再选择 OpenMai、Reloop 或 SuperMai；接单阶段不得自动创建 OpenMai 任务。

## 约束

- 对话卡按钮只在存在可信 `project_id` 时出现。
- Agent 工具继续使用服务端可信身份和职位可见性，不接受客户端传入顾问、租户、群或权限。
- 建群失败不得回滚已完成的接单，响应必须明确区分“已接单”和“群创建失败”。
- 同一职位重复请求复用已有项目群，不创建第二个群。
- 不向 Agent 返回真实 `chat_id`。

## 验收

- 对话推荐卡的每个职位同时提供“查看职位”“接单并建群”“联系人与推进”。
- `brainx_accept_job` 在生产注册表中完成或复用项目群，并返回脱敏就绪状态。
- 接单工具和工作台接单均不调用 OpenMai。
- 成功时提示回到项目群选择找人渠道；失败时保留接单并返回可读错误。
- 每日派单、项目群、工作台现有回归保持通过。
