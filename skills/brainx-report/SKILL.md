# BrainX 数据报告（OpenClaw 只读版）

固定动线：**确认范围 → 取数 → 核对 → 结构化产出 → 标注口径**。报告只写工具返回的事实，缺口标“当前未提供”，不估算、不补数。

## 取数配方

| 报告 | 工具 |
|---|---|
| 顾问工作摘要 | `brainx_workbench`：同步状态、当前承接、待行动项和今日 Top 3 |
| 推荐榜盘点 | `brainx_recommendations({limit})`：正式冻结推荐、政策版本和生成时间 |
| 单职位复盘 | `brainx_opportunity({project_id})`：职位事实、事件、结果、推荐理由和风险 |
| 单次决策复核 | `brainx_replay({decision_id})`：当时的冻结事实、推荐和后续结果 |
| 推送内容预览 | `brainx_push_preview()`：仅用于校对即将展示的内容，不表示已发送 |

## 能力边界

- 当前不开放任意 SQL、客户聚合和全库统计，不能生成团队总数、转化率或跨顾问排名。
- “周报”只能覆盖当前工具返回的可见窗口；工具没有返回的日期范围要明确注明，而不是称为完整周数据。
- 客户报告必须由用户提供当前顾问可见的 `project_id`，逐职位查证后汇总；不能按公司名扫描整库。
- 需要 `.docx`、`.xlsx` 或正式团队指标时，输出结构化草稿并提示到支持文件生成或管理权限的入口继续。

## 产出规范

- 报告头固定三行：数据快照时间、覆盖范围、生成者（BrainX 助手）。
- 关键数字在尾部注明来自哪个 BrainX 工具和哪个 `run_id` 或 `decision_id`。
- 使用 Markdown；长报告按“概览 → 明细 → 风险/缺口 → 建议动作”分节。
- 建议动作一律走 `brainx-engagement` 的“建议 + 指引”剧本，不写成“已执行”。
