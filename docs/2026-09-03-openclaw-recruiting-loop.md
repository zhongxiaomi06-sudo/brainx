# OpenClaw 招聘闭环（2026-09-03）

> 上级入口：[BrainX 文档书](README.md)
> 原始设计：[OpenClaw AI 招聘工作流 PRD](prd-2026-09-02-openclaw-ai-recruiting-workflow.md)

## 本轮用户决策

用户明确要求从“只读建议”升级为可执行的最短业务闭环。2026-09-07 用户进一步把自动项目群提升为当务之急，取代此前“自动建群后置”的排期判断。本文件是对 2026-09-02 PRD“首版只读”限制的后续产品决策；身份绑定、对象可见性、独立人才授权、确认、幂等和审计边界继续保留。

## 已接通链路

1. 每日推荐通过 BrainX 原生飞书互动卡投递；普通回复适配器已改用 OpenClaw typed hook，但当前锁定版 Feishu 自动回复路径未传入该 hook，真机仍会降级为文本，不能称为全部接通。
2. 顾问可用自然语言设置每天 1—4 个时间、每次 1—10 个职位；机器人复述并确认后保存。
3. 推荐卡按设置数量展示，每个职位包含结论、最多两条依据、最多两条风险和一个下一步。配置 `BRAINX_FEEDBACK_SECRET` 时，每行主按钮为“接单并建群”：顾问本次点击即为明确确认，签名链接自动加入项目、接单、幂等建立唯一项目群并投放职位卡；重复点击不重复建群，且不自动启动 OpenMai/SuperMai。卡片同时保留查看职位、回放和忽略。正式环境必须持久配置独立密钥；仅明确开启的本机回环环境可从本地登录密钥域隔离派生，避免服务重启使当天卡片失效。其他未配置场景安全降级为打开正式工作台，不显示伪一键按钮。
4. 私聊可读取授权职位负责人；不向模型暴露职位群 `chat_id`。
5. 用户确认后，机器人可接单并建立项目群；找人不会随建群自动启动，需在群内另行选择 OpenMai 或 SuperMai，也可补充本轮条件后再开始。
6. 授权 shortlist 候选人或项目找人结果中的结构化候选人，可进入共享重点名单并继续正式推进：
   - “重点关注”写入 `project_candidate_focus`，同一项目的已授权群成员后续问答可读取；来源项目群同时收到一张带 TTC 链接的人才卡。
   - 加入项目、准备联系、已发送、已回复、提交客户和面试仍使用按顾问隔离的 `consultant_candidate_cases`。
   - 所有动作强制校验发送人、群和项目范围，不扩大跨项目权限；联系方式仍仅限本人私聊和独立授权。
7. 候选联系方式仅在本人私聊、提供业务理由且存在 `scope=contact`、`purpose=candidate_contact` 的独立有效授权时返回。
8. 工作台可为已加入项目创建飞书项目群；发起人以及同职位下已加入项目、同租户且已完成 Agent 身份绑定的协作者一起入群，并成为该项目群允许的机器人发送人。系统不从昵称推断或邀请未绑定员工。外部调用前持久化启动状态，重复请求复用同一飞书幂等 UUID。创建成功后串行把新群追加到 OpenClaw 群 allowlist，并把项目协作者补入仅群聊 sender allowlist；只对该登记项目群关闭 `requireMention`，因为飞书卡片回调没有 @ 元数据，其他群继续保持全局 mention 门。随后投放职位卡片、绑定 `project_id ↔ chat_id`、登记消息上下文并激活 BrainX 的 sender/purpose/project 群范围。任一准入失败时保留群并在重试时补做，不提前发卡，也不扩大私聊权限。
9. “启动飞书寻访”只负责建立项目群、投放职位卡和完成接单，不检查 TTC 凭证，也不产生找人费用。群就绪后状态进入 `awaiting_method`，卡片提供“OpenMai 找人”和“SuperMai 找人”两个显式按钮。顾问可先在同群发送最新一条 `找人条件：……` 再点击渠道；没有这条消息时，OpenMai 使用职位事实，SuperMai 由后端根据职位事实生成条件。机器人消息、旧候选结果和普通群聊不能被当作找人条件。项目模式下两种渠道都关联真实 `project_id`，完成后由既有投递 worker 回到原项目群；同一项目已有运行中或已完成的共享搜索时不得因另一位协作者点击而重复触发费用。锁定版 OpenClaw 的卡片回调尚未向 Agent 暴露表单输入值，因此当前不伪造内联输入框，后续需在通道能力升级并真机验证后接入。
10. OpenMai 成功、需要补充画像或失败后写入持久投递账本，由 worker 自动回到原项目群：
    - 短澄清语句进入 `needs_input`；工作台允许顾问补充最多 2000 字岗位画像后显式重跑。
    - 成功结果要求 6–10 人和逐人评估。筛选条件用纯文字，候选人使用飞书原生整洁表格。
    - 每行只提供“重点关注”；经 `KEEP_FOR_REVIEW` 写入项目共享重点名单，并在来源项目群幂等投放带 TTC 人才库链接的人才卡。
    - 表格后提供 OpenMai / SuperMai 两个继续找人按钮。BrainX 累计项目历史 TTC 编号并传入下一轮；Agent 不能直接提供排除字段。`continue_search=true` 只用于该按钮任务的第一次启动调用，后续状态轮询必须改为 `false` 或省略，避免结果刚完成就被误当成再开一轮。
    - SuperMai 外部引用只有带官方 TTC 链接时才进入排除名单；无法确认编号时不启动下一轮。
    - 当前链路不创建逐人话题、不发送简历附件，卡片默认清除电话与邮箱。
    - 候选表格不再显示专门建群按钮。顾问在职位唯一项目群自然语言说“为这个人建群”或点名候选人要求建决策群，即构成本次明确确认；BrainX 对已授权候选人自动加入项目重点名单后幂等建群，按概览、匹配、原群证据、待核实项迁移原群明确提及此人的最近最多 8 条脱敏讨论，并登记相同项目范围。原群文字只作为业务证据，不作为机器人指令。指代不唯一时机器人只追问姓名，不猜测。新群首卡提供查看 TTC 人才、生成报告和更新报告；`/report` 把当前群新增文字证据写入新版本飞书云文档。新群不迁移其他候选人、联系方式或简历原文。
    - 少于 6 人的结果会保留并以橙色告警回群，不在后台擅自增加搜索费用。
    - 只有真实送达后项目才标记完成；连续五次未送达时只重试原投递，不重新运行 OpenMai。
    - 每条消息使用稳定幂等键；超过一小时的遗留 RUNNING 任务失败关闭，要求顾问明确重试。

## 尚未伪装为已完成的能力

- 对外发送联系话术：当前没有稳定的候选外部联系渠道连接器。机器人可以生成话术；只有外部渠道真实成功后才能记录 `RECORD_OUTREACH_SENT`。
- 自动建群真机验收：代码链路已接通；仍需目标租户批准建群权限，并用真实顾问身份验证成员、机器人、职位卡片和重复点击行为。
- 工作台候选 Case 专页：底层状态与飞书候选决策群已可共享，现有深链先打开职位详情并预填候选分析；专门的 Web 可视化操作区仍待后续前端审核。
- 普通回复统一卡片化：插件 1.1.5 已在本机目标环境发布并随网关启动，原生每日推荐实卡已验证；普通自动回复仍需修复 OpenClaw Feishu 的 hook 传递。
- 写动作真机验证：本轮没有执行接单、启动找人或候选推进，不能把工具接入记为业务写闭环已验收。

## 工具确认规则

`brainx_update_push_preferences`、`brainx_accept_job`、`brainx_start_candidate_search`、
`brainx_record_job_progress` 和 `brainx_candidate_workflow` 都要求本次调用携带明确的 `confirm=true`。
模型发起动作必须先复述对象和动作，历史消息中的泛化同意不能替代本次确认；候选行“重点关注”按钮本身是 `KEEP_FOR_REVIEW` 的本次确认。顾问当轮明确说“为这个人建群”或点名要求建决策群时，该消息本身是 `CREATE_DECISION_GROUP` 的确认。
重点关注只向当前授权项目群投放不含联系方式和简历原文的人才卡，卡内 TTC 链接继续由 TTC 登录与权限控制。
