## 1. 目标

建立默认关闭的 `agentic-ranking-v1` 展示兼容层，使同一 LIVE run 在数据库、API、工作台和飞书中保持 Agent 原序、原理由、原证据和原不确定项。读取开关关闭时继续使用已标记的 `baseline-1.1`；本阶段不执行生产切读、发送或发布。

## 2. 行为要求

### S1｜只读 LIVE 原序

A 读取只能选择当前顾问的 `LIVE/PUBLISHED` 或 `LIVE/ABSTAINED`，永不读取 SHADOW。游标绑定 `engine/run_id/search/rank`；搜索只能过滤，不能压缩或改写原始 rank。A 请求旧分数排序时必须拒绝，不能在服务端或前端二次评分、补榜。

### S2｜事实与状态忠实

接口显式返回 `engine/run_id/rank/reason/evidence_refs/uncertainties/generated_at` 及候选数、实际推荐数。读取时重新检查职位可见性、开放状态、HC、忽略和当前承接；失效项直接撤下且保留 rank 缺口。正在生成、弃权、失败和存在较新失败运行时分别返回可区分状态；展示旧成功结果必须显式标记，不伪装为最新成功。

### S3｜Web 与飞书同一投影

工作台和飞书卡片消费同一展示投影。A 页面只提供“Agent 原序”，卡片显示理由、权衡、证据引用、不确定项和建议动作，不显示旧总分、六维分、概率或模型置信。`200` 只能称候选/检索上限，推荐数必须取真实 A items 数。

### S4｜主动设置替代旧权重

A 设置开放画像关键词、排除公司、排除职位、排除城市和容量上限的校验与自助保存。旧六维权重只在明确标识的 `baseline-1.1` 历史区可见，且不连接 A。设置变更继续追加画像版本，不能擦除未提交字段。

### S5｜审核与回滚边界

Storybook 覆盖原序、冻结分页、生成中、弃权、失败、旧结果、撤权/排名缺口、动作失败/幂等和窄屏。中央台账、当轮审核记录、施工清单和组件库说明在同一提交同步；只能记录本地 Storybook/代码接入状态，不得冒充用户审核、目标环境发布或真实数据验证。关闭 A 读取开关即可回到明确标识的历史 baseline。

## 3. 验收

1. 同一 LIVE run 的数据库、API、Web 映射和飞书卡片顺序、rank 与文案逐项一致，SHADOW 不可读。
2. A 路径不返回或补造 score、概率、置信与理由；不足 20 条、弃权和撤下如实展示。
3. 翻页绑定 run，较新运行不静默混入；搜索后仍保留原 rank；旧排序请求失败。
4. 主动偏好、排除项和容量保存后生成新画像版本，非法类型、数量和范围失败。
5. 生成中、旧结果、无结果、失败恢复、权限撤销及动作幂等有自动回归与 Storybook 场景。
6. 专项、快速和完整门禁通过。
