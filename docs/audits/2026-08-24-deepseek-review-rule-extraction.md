# DeepSeek 代码审查的规则提炼

> 上级目录：[BrainX 文档书](../README.md)
>
> 来源：用户提供的 DeepSeek 全仓审查报告
>
> 使用原则：报告属于外部审查意见；只有经当前仓库证据复核的模式才转化为规则，未复核的具体 bug 不视为既定事实。

## 已复核的工程模式

2026-08-24 对当前工作区进行了只读核对，确认以下模式真实存在：

- 五个手写文件超过 500 行：`cockpit-radar-data.ts` 851 行、`brainx-api.ts` 821 行、`src/server.js` 789 行、`workbench.tsx` 779 行、`globals.css` 738 行；
- `.dockerignore` 排除了数据库，但没有排除 `data/.secret`；
- `src/push.js` 调用 `lark-cli` 时缺少超时；
- `docs/SECURITY.md` 使用了与迁移和代码不一致的令牌字段名；
- `.github/workflows/ci.yml` 与 `.github/workflows/pr-test.yml` 并存，存在重复门禁和运行时漂移风险；
- 部分 CLI 会显示 `complete=0`，但退出码约定不统一；
- 测试报告指出根目录 CSV 缺失时测试失败，说明测试夹具存在工作区依赖风险。

这些事实说明问题不是单个 bug，而是文件规模、外部操作、失败语义、环境自包含和文档一致性缺少统一门禁。

## 已纳入的长期规则

以下规则已写入 [多 Agent 协作准则](../../AGENTS.md) 和 [上传前完整验证](../standards/PRE_PUSH_VERIFICATION.md)：

1. 手写源代码、测试和配置文件最多 500 个物理行；现有超限文件不得增长，功能性修改前先拆分。
2. 禁止整文件关闭 Lint、压缩成长行或用字符串藏代码来规避规模限制。
3. Docker、归档和发布包必须排除密钥、本地数据库与用户数据。
4. 网络请求、外部命令和长任务必须有有限超时及清理路径。
5. 测试必须自包含，测试夹具放入明确目录，不依赖个人路径或稀疏检出之外的文件。
6. 分页、空输入、非法值、并发、幂等和租户隔离必须覆盖失败与边界测试。
7. 持久化服务失败不得静默写入易失内存；降级必须显式可见并接受验证。
8. CLI 和数据管道遇到失败或不完整结果必须返回非零退出码。
9. 容器必须验证密钥排除、运行用户写权限、持久卷和真实启动。
10. CI、迁移与文档必须保持单一权威入口和可执行的一致事实。

## 规则边界

- 500 行限制针对手写源代码、测试和配置；自动生成文件、lockfile、固定数据和第三方代码仅在可明确识别时例外。
- 规则用于防止同类问题继续产生，不代替对报告中具体问题逐项复现和修复。
- 现有超限文件是已知技术债；在被功能性修改前必须先拆分，不能通过无关 commit 扩大范围。
